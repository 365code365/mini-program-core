# play-fighter 拳魂（横屏格斗）
可玩示例，不是测试夹具。照 90 年代街机格斗做的单人对战电脑，三局两胜，每回合 60 秒。角色、招式名都是原创的。

## 操作
- **左半屏**：浮动摇杆，按在哪里，哪里就是摇杆中心，支持 8 个方向。←→ 走，↑ 跳（可斜跳），↓ 蹲；**按住「后」防御**，蹲着按后才挡得住下段。双击前冲刺，双击后后撤（后撤前几帧无敌）。
- **右下**：A 轻拳、B 轻脚、C 重拳、D 重脚；「波」「升」各放一个必杀技；「超」在能量够一格时放超必杀。支持多指同时按，手指滑到别的键上会自动换键。
- 搓招也能放：↓↘→ + 拳 = 波，→↓↘ + 拳 = 升。蹲着按脚是扫腿（重脚会击倒），空中按任意攻击键是飞踢（中段、必须站着挡）。
- 连段：普通技打中或被挡后，马上按「波」「升」「超」可以取消成必杀；轻拳可以连打三下。连击伤害逐段递减。
- PC：WASD / 方向键移动，J K U I 对应 A B C D，L 波，O 升，空格 超，P / Esc 暂停。

## 系统
- 帧数据（发生、持续、收招、硬直、推开距离、上中下段）在 `js/data.js`，逻辑按每秒 60 步走，和屏幕刷新率无关。
- 打击感来自几处：打中时双方定格 6~14 帧，镜头震动，叠加混合的火花，受击闪白，重击和冲刺留残影，KO 时慢放并闪白。
- 能量（3 格）在打中和被打时都会涨，跨回合保留。两个飞行道具相撞会互相抵掉，超必杀的大波能吃掉普通波。
- 电脑对手输出和屏幕按键同格式的输入，所以它出招、防御走的是和玩家同一条代码路径。它的「反应」是看若干帧以前的局面，难度（简单、普通、困难）调的是反应延迟、防御率、对空率和连段率。

## 美术
角色动作、两个场景、封面都由豆包 Seedream 4.5 生成（`tools/gen-fighter-art.py`）。先生成每个角色的设定图，再把设定图作为参考图逐个生成 16 个动作，这样脸和服装能保持一致。生成后抠掉绿底，按「身高系数」统一大小，算出脚底锚点，装进每个角色一张图集（`art/<角色>.webp` + `art/manifest.json`）。

走路是 4 帧循环（迈步 → 过渡 → 换脚 → 并脚），按走过的距离取帧（走快换得快、停下就停），锚点取躯干中心（按脚底取的话分腿那帧会往前跳）；身体随步伐起伏、前进微前倾后退微后仰，落脚时扬尘、响脚步声，后退倒着放。其余动作是单张关键帧，动起来靠程序处理：待机呼吸、出招前蓄力后缩、受击抖动、浮空翻转、残影。湿漉漉的城市场景还会画地面倒影。场景氛围（雨、落樱）和全部特效都是代码画的。

## 音效
`sfx/*.mp3`（28 条，约 290KB）由 `tools/gen-fighter-sfx.py` 离线合成：打击声是瞬态 + 下滑的「身体」+ 带通噪声质感几层叠加，再过软削波失真和卷积混响；火焰波是扫频低通噪声 + 噼啪，冰电波是不协和泛音 + 电弧，超必杀起手是「吸」上去的倒混响接一记锣。解说（ROUND ONE / FIGHT / K.O. / PERFECT …）用 macOS 的 say 生成后降调、压缩、加大厅混响。
手机外放放不出 150Hz 以下，所以打击声的主体放在 150~600Hz，并在 80Hz 做了低切；脚本收尾会打出 150Hz 以下能量超过 45% 的条目。游戏里每条解码一次（`js/audio.js`），每次播放随机变调 ±4%、音量 ±10%，同一条最多同时响 3 个，解说一次一条。重新生成：`python3 tools/gen-fighter-sfx.py [名字…] [--wav]`。缺了某张图会退回代码画的剪影，游戏照常能玩。

重新生成：`ARK_API_KEY=… python3 tools/gen-fighter-art.py`（原图缓存在 `target/fighter-art/raw/`，只补缺的）；只改加工参数：`--process-only`；重画某几张：`--redo yan_ck,shuang_hp`。

## 结构（每个文件 < 500 行）
`game.js` 主循环与画面切换；`js/data.js` 角色与招式表；`js/fighter.js` 角色状态机与搓招识别；`js/fight.js` 判定、防御、飞行道具、回合与镜头；
`js/ai.js` 电脑；`js/controls.js` 屏幕摇杆与按键；`js/render.js` 场景与角色；`js/fx.js` 粒子与飞行道具；`js/hud.js` 血条、计时、连击、播报、超必杀切入；
`js/scenes.js` 标题、选人、VS、暂停、结算；`js/audio.js` 音效解码与播放；`js/gl2d.js` WebGL 2D 批量绘制（play-flappy 那份的基础上加了贴图与叠加混合）；`js/base.js` 共用底座。

用到：主画布、rAF、多点触控、onKeyDown/onKeyUp、WebGL 贴图（Image → texImage2D）、WebAudio（decodeAudioData + BufferSource + Gain）、vibrateShort、存储、getLaunchOptionsSync。

无头试玩（两边都是电脑）：`./target/release/mini-app-window sample-game/play-fighter --query auto=1 --frames 1800 --eval 'JSON.stringify(__play())' --snapshot target/_play/fighter`。
加 `boxes=1` 会画出受击框（绿）和攻击框（红）；自对战默认静音，`sound=1` 打开；`perf=1` 每 20 帧往日志打一行各段耗时（逻辑、世界、特效、氛围、HUD、顶点数）和玩家状态，真机 `adb logcat | grep '\[perf\]'` 看。

真机（一加 PLY110，60Hz，auto=1 自对战 15 秒）：屏上 831 帧、按 60fps 重复 0 次；引擎每帧工作中位 13.6ms、p99 19.1ms，其中 2~5ms 是 GPU 交出下一块缓冲的等待（第一次碰帧缓冲时记账），JS 画一帧约 8ms。120Hz 下还不够，下一步是把 HUD 的静态部分录成图层。`__goto('title' | 'select' | 'vs' | 'fight')` 可以直接跳到某个画面截图。
