# 工程化结构：单文件 500 行上限

按单一职责组织代码。**单个 `.rs` 超过 500 行就要想办法重构**，否则改一处要在无关代码里翻半天，优化也无从下手。

## 硬性约定

- 新增文件一律控制在 500 行以内。
- 已有文件在被改动时，如果已经超过 500 行，优先顺手按职责拆出去，而不是继续往里堆。
- 目录模块化：一个概念一个目录（`mod.rs` 放类型定义与构造，子模块按职责分）。参考 `src/renderer/wxml_renderer/`：
  `entry`（对外入口）/ `layout`（建树+布局+缓存）/ `draw`（裁剪与分派）/ `draw_interactive`（主绘制路径）/ `animation` / `pressed` / `fixed_layer` / `hit_test` / `interactions` / `invalidate`。

## 允许的例外（需在文件头注明理由）

- **数据表**：静态查表（如行政区划、字体度量表）本身就是一大坨数据，拆开反而更难维护。
- **单一算法主体**：一个不可分割的算法/状态机，硬拆会制造出只被调用一次的碎片函数，反而更难读。
- **平台胶水**：与外部框架签名强绑定的巨型 match（如窗口事件分发），拆分会引入大量参数透传。

例外要写清楚「为什么不拆」，不能只是"懒得拆"。

## 重构的铁律：先证明等价

重构（纯搬迁）与改行为**必须分成两次做**，不能混在一个改动里。纯搬迁必须能证明等价：

```bash
# 拆分前后各跑一次固定动画时钟的整帧快照，逐字节比对
./target/release/mini-app-window <app> --time 2 --snapshot target/before
# ...重构...
./target/release/mini-app-window <app> --time 2 --snapshot target/after
# 两份 PNG 的 md5 必须完全一致
```

`--time` 必须给，否则动画相位与倒计时会按真实时间跑，比对结果没有意义（swiper 自动播放、`setTimeout` 都是墙上时钟驱动的）。

## 命名与注释

- 注释写**为什么**，尤其是"为什么不用看起来更自然的那种写法"。踩过的坑要留在代码里，否则下一个人会原样再踩一遍。
- 诊断开关要留下来并写进 README（`MINI_FPS` / `MINI_LAYOUT_LOG` / `MINI_SCROLL_LOG` / `MINI_NO_DAMAGE`），它们是排查问题的第一手段。
- 不要留下与代码不符的注释。注释说"不更新 X"而代码更新了 X，比没有注释更糟。
