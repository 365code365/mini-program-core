# 02 架构设计

## 0. 设计原则

1. **小程序零回归**。小游戏是新增的运行模式，不改小程序的绘制路径、失效分析、事件语义。每一期都要证明小程序的七项回归逐字节不变（05 §6）。
2. **CPU 是参考实现，永远可用**（steering 10）。2D 小游戏在 CPU 后端上必须完整可用；GPU 只是更快的合成与上屏。WebGL 是唯一的例外，取舍见 §10 与决策 D-2。
3. **后端只管画**。帧循环、rAF、输入、音频、定时器都与后端无关，两个后端的 JS 可见行为完全一致。
4. **先拿数据再优化**（steering 30）。性能目标先写成可判定的数字，做完用真机量；没有数据不做「可能更快」的改动。
5. **先证等价，再改行为**（steering 20）。抽取共享件、prelude 分组都是纯搬迁，单独提交，用 md5 证明。
6. **单文件 ≤ 500 行**（steering 20）。§14 的文件布局按职责拆好，例外写在文件头。

## 1. 运行模式与包识别

新增 `src/app_profile.rs`：

```rust

/// 有 game.json → 小游戏；有 app.json → 小程序；两者都有 → 报错（不猜）；都没有 → 报错
```

## 2. GameEngine 与 MiniEngine 的关系（决策 D-1）

`doc/架构扩展与小游戏.md` §2 规划的是 `Engine { kernel, scene: Box<dyn Scene> }`，要先从约 90 个字段的 `MiniEngine` 拆出 `Kernel`。
那条路最终最干净，但改动面覆盖小程序的帧调度全链路（steering 30 要求按顿挫重验），风险集中在已经稳定的小程序上。

**推荐（D-1 方案 B）：新建平级的 `GameEngine`，只把真正通用的件抽成独立结构，两边各自组合。**

```text
            MRApp（ffi_app.rs）
            └── kind: AppKind
                 ├── Mini(MiniEngine)   ← 原样不动（只把下面几个字段换成共享件，纯搬迁）
                 └── Game(GameEngine)   ← 新增 src/game/

  共享件（从 MiniEngine 抽出，纯搬迁，04 G0.6）：
    host::backend_slot::BackendSlot   env / host_pref / backend / device_info / surface / native_surface /
                                      gpu / gpu_parked / gpu_warming / gpu_failed / backend_changed /
                                      frame_presented / present_pending（engine_backend.rs + engine_gpu.rs 的方法搬过去）
    host::events::HostEvents          已是独立结构（engine_events.rs:34），直接复用
    frame_clock::Anchor + host_clock  帧时刻换算
    host::cpu_affinity / engine_stats 大核绑定、MINI_FPS 统计
```

- `GameEngine` 不包含页面栈、WXML 渲染器、tabBar、导航栏、侧滑、picker、滚动控制器。
- 覆盖层（Toast / Loading / Modal / ActionSheet）的**状态与绘制**复用 `host::ui_overlay`，命中复用同一套几何（02 §7.4）。
- FFI 按 `AppKind` 分派。只对小程序有意义的函数（`mr_app_launch` 的路由参数、`mr_app_navigate`、`mr_app_back`、`mr_app_page_depth`、`mr_app_wheel` 的页面滚动、分栏相关、同层视频帧）在小游戏实例上：`launch` 忽略路由只启动；`navigate` 返回 0；`back` 返回 false（宿主据此走系统返回，引擎不派发任何事件）；`page_depth` 返回 0；其余返回 0 并在 `mr_app_last_error` 写「小游戏实例不支持 <函数名>」。不崩、不 panic。
- 将来要做 Kernel/Scene 时，`GameEngine` 就是 `MiniGameScene` 的雏形，抽出的共享件就是 `Kernel` 的一部分，不白做。

方案 A（先做 Kernel/Scene 再做游戏）与 B 的取舍见 06 §1 D-1。

## 3. JS 环境

### 3.1 prelude 分组

`src/js/api.rs` 的 `PRELUDE` 改成三组（G0 纯搬迁：小程序装的集合与顺序**逐项不变**，`prelude_names()` 前后相同）：

| 组 | 内容 |
|---|---|
| `core` | module（**拆出** `window/self` 别名，见 §3.2）、console、fake-clock、wx-object、codec、timer、storage、network、socket、fs、audio、webaudio、net-socket、device、system、host、host-capabilities、base-ext、app-info、media-ext（只取 offscreen 与音频那部分，见下）、api-probe（必须最后） |
| `mini-program` | ui、canvas、media、query、canvas2d、app-page、app-hooks、lifecycle、page-components、route、host-media、tabbar、host-objects、route-ext、page-ext、worker-mq、animate、worklet、component、component-tree、wxs |
| `mini-game` | game-global、game-canvas（主画布 / 离屏 / 2D 原生类的 JS 外壳）、game-raf、game-touch、game-lifecycle、game-ui（Toast/Modal/键盘/按钮）、game-subpackage、game-worker、game-audio-ext（`setInnerAudioOption` 等）、game-compat（TextEncoder/atob/performance） |

- 小程序装 `core + mini-program`，顺序与今天完全一样（`api-probe` 仍然最后）；小游戏装 `core + mini-game + api-probe`。
- 现有文件里混着两种语义的（`media-ext.js` 同时有 `createOffscreenCanvas` 与旧版音频；`system.js` 有 ActionSheet；`app-info.js` 有胶囊）：G0 只分组不拆文件；G1 起按需把游戏要的部分拆成独立文件（每次拆分单独证明小程序 prelude 输出不变：同一组 `__native_*` 引用、`native_bridge_contract_tests` 全绿）。
- `api-probe.js` 的「未实现 API 返回 undefined」语义对小游戏保留（框架用 `typeof` 探测）。

### 3.3 守护（生产必备）

- **死循环**：`rquickjs::Runtime::set_interrupt_handler`。每进入一次 JS 回调（rAF、定时器、事件、回包）记开始时刻；单次回调超过 `MINI_GAME_WATCHDOG_MS`（默认 5000ms）中断，抛 `InternalError: interrupted`，按 `wx.onError` 上报，并向宿主发 `error` 事件（`{message, stack, kind:'watchdog'}`）。不自动杀进程，宿主决定。
- **内存上限**：`Runtime::set_memory_limit`，默认取宿主 `DeviceInfo.totalMem` 的 25%、上限 1GB，可由创建选项 `jsMemoryLimitMB` 覆盖；超限抛 `out of memory` → `wx.onError` + `memoryWarning` 事件。
- **GC**：`wx.triggerGC()` → `Runtime::run_gc()`；`onHide` 时主动 GC 一次；`trim_memory` 时 GC + 清图片解码缓存。
- **错误上报**：所有回调外层 try/catch → `wx.onError` 监听者（官方签名 `{message, stack}`）+ 未处理 Promise 拒绝 → `wx.onUnhandledRejection`（`{reason, promise}`）。同时写宿主日志。异常不能中断帧循环：一个 rAF 回调抛错，同批其余回调照常执行。
- **日志洪水**：`console.*` 经 `__print_buffer` 每帧取走（`engine_events.rs:151`）。游戏实例每帧最多取 500 行、单行截断 4KB，超出只计数，下一帧打一行「…丢弃 N 行日志」；`MINI_GAME_LOG_ALL=1` 关闭限制（09 §2.4）。
- **原生 panic**：游戏实例的每个 FFI / JNI 入口包 `catch_unwind`，捕获后实例进入 poisoned 状态、之后的调用都返回失败值，宿主收到一次 `error{kind:'panic'}` 事件（09 §2.1）。不能让 panic 穿过 `extern "C"`（Rust 1.81 起会 abort 宿主进程）。
- **数值校验**：JS 传进原生的数值先校验（NaN、无穷、负数、超上限），失败抛 `TypeError` / `RangeError`，原生代码里不 `unwrap` 外部输入。
- 以上开关与默认值写进 README（steering 20：诊断开关要写进 README）。

## 4. 帧循环

### 4.1 一次 `pump_ex(now_ms)` 的顺序（GameEngine）

```text
 0. 帧时刻：now_ms>0 → frame_clock::set(anchor.frame_instant(now_ms))；否则取单调钟
 1. 输入：取出自上一帧以来排队的触摸 / 键鼠事件，按到达顺序逐个派发
          （覆盖层先命中 §7.4；每个事件之后 pump_jobs）
 2. 定时器：按帧时刻判到点（§4.4），逐个触发，每个之后 pump_jobs
 3. I/O 回包：网络、WebSocket、TCP/UDP、文件异步、图片解码完成、字体、音频事件、宿主回包、宿主推事件
 4. pump_jobs（微任务）
 5. rAF：若本帧是「rAF 帧」（§4.2）——取出当前全部 rAF 回调（快照），以同一个时间戳依次调用，
          每个回调之后 pump_jobs；回调里新注册的进入下一批
 6. 主画布提交：2D → 本帧画过就标脏（立即模式已画进后备缓冲，§5.2）；WebGL → 本帧有 draw 调用就 swap（§10）
 7. 合成上屏：游戏层 + 覆盖层 + 胶囊 → GPU present 或 CPU compose（§5.4）
 8. 标志：FRAME_NEW / PRESENTED / PENDING / BACKEND_CHANGED / EVENTS / WANTS_MORE（§4.5）
 9. frame_clock::set(None)；MINI_FPS / 慢帧日志
```

- 输入放在 rAF **之前**：手指这一帧的位置在这一帧的 rAF 里就能用上（延迟一帧以内）。
- 第 5 步只在「rAF 帧」做；非 rAF 帧（高刷屏上 60fps 节拍的空档）只做 1~4、7（有覆盖层动画时）。

### 4.2 rAF 语义与 60fps 节拍

- 官方：rAF 默认 60fps，`wx.setPreferredFramesPerSecond(fps)` 有效范围 1~60。**高刷屏上也是 60**，这是对齐点，不是性能不足。
- 回调参数：`DOMHighResTimeStamp`（毫秒，带小数），取本帧的帧时刻（vsync 时刻换算到 `performance.now()` 同一时间轴）。同一批回调拿到同一个值。取证确认参数存在与时间轴（G0.2）。
- 返回值：正整数 id，单调递增，从 1 开始；`cancelAnimationFrame(id)` 取消尚未执行的；取消已执行或不存在的 id 无副作用。
- 批次：执行前快照，回调里 `requestAnimationFrame` 进入下一批；回调里 `cancelAnimationFrame` 同批里尚未执行的那个，**不执行**（与浏览器一致）。
- 节拍算法（`src/game/raf_pacer.rs`）：**按理想时刻累加，不按上一次实际时刻**。全部用整数微秒运算（避免浮点在边界上忽左忽右）：
  - `T = 1_000_000 / fps`（µs）；`period` = 显示器周期，取最近 16 个 vsync 间隔的中位数；
  - 首个 rAF 帧：`ideal = t`；之后每个 vsync 时刻 `t`：`t >= ideal + T - period/2` 时是 rAF 帧，然后 `ideal += T`；
  - 落后保护：若 `t - ideal > 2T`（卡顿、后台回来），`ideal = t`（不补帧）。
  - 结果：60Hz 每帧；120Hz 恰好隔一帧；144Hz 下间隔为 2、3 个周期交替（13.89 / 20.83ms，平均 16.67ms）；90Hz 下 1、2 个周期交替。
  - 反例（不要这样写）：`t - t0 >= T - period/2`（t0 为上一次实际时刻）。144Hz 上它每 2 个周期就触发一次，实际跑 72fps——误差会累积，不会自己回到 60。L1 用例 K3 专门守这一条。
- **90Hz / 144Hz 的不均匀问题**：60 不能整除 90，按上面算法是 1、2、1、2…个周期交替（11.1/22.2ms），屏上就是抖。宿主必须把显示刷新率请求到 60 的整数倍：
  - Android：`Surface.setFrameRate(fps, FRAME_RATE_COMPATIBILITY_FIXED_SOURCE)`（API 30+），API < 30 用 `WindowManager.LayoutParams.preferredDisplayModeId` 选 60/120Hz 模式；
  - iOS：`CADisplayLink.preferredFrameRateRange = (fps, fps, fps)`（ProMotion 设备上 120 = 2×60）；
  - 系统不给就记日志「显示刷新率 90Hz 无法整除 60fps，节拍不均匀」，判据里单独列出（05 §5）。
  - `setPreferredFramesPerSecond` 改了 fps 时，宿主重新请求刷新率（事件 `preferredFps`）。
- 后台（`onHide`）：不执行 rAF、不出帧；回前台第一帧的 rAF 时间戳是真实时刻（不会补跑错过的帧）。

### 4.3 时间轴

| 时钟 | 来源 | 用途 |
|---|---|---|
| `performance.now()` / `wx.getPerformance().now()` | 引擎启动为 0 的单调钟（毫秒，小数） | 游戏逻辑、rAF 参数 |
| rAF 参数 | 本帧帧时刻在同一时间轴上的值 | 动画插值 |
| 触摸 `timeStamp` | 事件发生时刻在同一时间轴上的值（宿主事件时间换算，Android `MotionEvent.getEventTimeNanos`、iOS `UITouch.timestamp`） | 手势速度 |
| `Date.now()` | 墙上时钟（`MINI_FAKE_NOW` 可钉住） | 业务 |

无头模式（`--hz 60 --frames N`）下帧时刻是确定序列 `n × 1000/hz`，`performance.now()` 跟着它走，测试才能逐帧复现（05 §2.3）。

### 4.4 定时器改用帧时钟

`MiniApp::process_timers` 用 `Instant::now()`。游戏模式改为「本帧帧时刻」判到点（`GameEngine` 自己的 `TimerQueue`，`BinaryHeap<(due, seq)>`，不用 HashMap 扫描）：
- 同一帧里 rAF 与定时器的时间一致；无头可复现。
- 回前台：到点的 `setInterval` 只补触发**一次**并把下一次排到 `now + delay`（不能一口气补几百次）；`setTimeout` 到点的按顺序触发。
- `delay < 1` 按 1；`setInterval(fn, 0)` 按 1ms 处理但每帧最多触发一次（防止空转占满一帧，浏览器同样有 clamp）。嵌套超过 5 层的 `setTimeout(0)` 按 4ms clamp（HTML 规范）。取证确认微信是否 clamp（G0.2），以取证为准。

### 4.5 什么时候要下一帧（`FRAME_WANTS_MORE`）

任一成立：有挂着的 rAF；有 1 秒内到点的定时器（更远的定时器由宿主用定时唤醒，见下）；触摸进行中；覆盖层动画中；有在飞的网络 / 解码 / 加载；音频事件需要派发（`timeUpdate` 每 250ms，播放中按 4Hz 要帧，不是每帧）；`present_pending`。
都不成立时宿主停 vsync。**远期定时器**：新增标志位 `FRAME_WAKE_AT = 128` + `mr_app_next_wake_ms()`，宿主据此 `postFrameCallbackDelayed` / `DispatchQueue.asyncAfter` 唤醒，避免为了一个 30 秒后的定时器每帧空转（小程序侧不使用该位，行为不变）。

## 5. 画布与合成

### 5.1 画布对象模型（`src/game/canvas/`）

| 项 | 规则 |
|---|---|
| 主画布 | 第一次 `wx.createCanvas()`；之后的都是离屏。主画布显示区域 = 整个窗口（逻辑尺寸 `windowWidth × windowHeight`） |
| 默认尺寸 | `width/height` 默认 = 窗口逻辑尺寸（取证 G0.2 确认；社区反馈 393×873 这类逻辑值）。离屏默认 300×150（HTML 默认），取证确认 |
| 改尺寸 | 设 `width/height` → 后备缓冲按新尺寸重建、清成透明、状态复位（HTML 语义）；主画布的**显示区域不变**，内容缩放填满窗口（§5.4） |
| 上限 | 单边 ≤ 4096，面积 ≤ 4096×4096（与现有离屏一致）；超出按上限截断并打一行警告；取证确认真机上限与行为 |
| 上下文 | `getContext('2d' \| 'webgl' \| 'webgl2', attrs)`；同一画布第一次拿到什么类型，之后只能拿同类型（再要别的返回 `null`）；同类型多次调用返回同一个对象 |
| 画布方法 | `toDataURL()`、`toTempFilePath({x,y,width,height,destWidth,destHeight,fileType,quality,success,fail,complete})`、`toTempFilePathSync`；读的是**后备缓冲**（不含覆盖层） |
| 所有权 | 画布属于 `GameEngine` 实例（`GameCanvases`），**不进**进程级 `CANVAS_MANAGER`；JS 对象释放（GC finalizer）时释放后备缓冲 |

### 5.2 2D 上下文绑定

- 用 rquickjs `#[class]`（`classes` feature 已开）实现 `CanvasRenderingContext2D` 原生类，方法直接调 `Canvas2DContext`，**立即模式**：调用返回时像素已经写进后备缓冲。JS→原生每次调用的成本目标：`fillRect` 单次 ≤ 0.3µs（桌面）——G1 探针实测后定死。
- 不再走 JSON 指令、不记 2d 日志（游戏画布的后备缓冲不会因布局重建，不需要重放）。
- 复用 `Canvas2DContext` 的光栅代码（填充、描边、渐变、图案、阴影、合成模式、clip、虚线、变换、文字），`commands.rs` 的 JSON 解释器只给小程序用。为此把 `Canvas2DContext` 的「状态 + 光栅」与「JSON 解释」分开（纯搬迁，G2.1）。
- 属性 getter/setter（`fillStyle`、`font`、`globalAlpha`…）按 HTML Canvas 规范：非法值忽略、保留旧值；`fillStyle` 读回规范化字符串（`#rrggbb` 或 `rgba(r, g, b, a)`）；取证确认微信读回格式。
- `drawImage(source, …)` 的 `source`：`Image`（§5.3 已解码）、离屏 `Canvas`、主画布（自绘）。未加载完成的 `Image` 静默不画（HTML 语义）。
- `getImageData/putImageData/createImageData` 走二进制桥：返回 `{width, height, data: Uint8ClampedArray}`，非预乘 RGBA（与引擎内部一致，无需转换）。
- 文本：`font` 串按 CSS 简写解析（`[style] [variant] [weight] size[/line-height] family[, family…]`），family 查 `text_faces`（`wx.loadFont` 注册的 + 内置字体），找不到回落默认；`measureText` 返回 `TextMetrics`（至少 `width`，取证决定是否提供 `actualBoundingBox*`）。
- 状态栈深度上限 1024（防恶意 `save()` 不 `restore()` 吃内存），超出忽略并警告。

### 5.3 图片

- `wx.createImage()` → 原生类 `Image`：`src`（包内路径、`wxfile://`、`http(s)://`、`data:` URI）、`width/height`（自然尺寸，加载前为 0）、`onload/onerror`、`complete`、`referrerPolicy`。
- 设置 `src` → 提交到解码线程池（`src/game/image_loader.rs`，2 个线程，按 `src` 去重：同一 src 并发设置只解码一次）；网络图先下载（复用 `net::fetch_bytes`）。完成后在 pump 第 3 步回填尺寸并调 `onload`；失败调 `onerror`（`{errMsg}`），取证确认参数形状。
- 解码结果放进**按实例**的 `ImageStore`（`Arc<DecodedImage>`，RGBA8），预算默认 256MB（可配），LRU 只淘汰**没有 JS 对象引用**的条目；有引用的超预算时发 `memoryWarning` 而不是淘汰（淘汰会让 `drawImage` 画空）。
- 重复设置同一个 `src` 不重新解码；把 `src` 设成空串释放引用。
- GIF / APNG / WebP 动图：只取第一帧（与 Canvas 规范一致）。

### 5.4 游戏层与合成

`FrameLayers` 增加一种形态（`src/compositor/mod.rs`），小程序侧所有字段不变：

```rust
pub struct GameLayer<'a> {
    pub canvas: &'a LayerCanvas,   // 主画布后备缓冲（RGBA8 非预乘），带脏区记账
    pub src_w: u32, pub src_h: u32,  // 后备缓冲像素尺寸（canvas.width/height）
    pub dst: (u32, u32, u32, u32),   // 显示到输出缓冲的矩形（设备像素），默认整屏
    pub filter: GameFilter,          // Nearest | Bilinear（默认 Bilinear，见下）
    pub opaque: bool,                // 主画布不透明：底下不用合成黑底
}
// FrameLayers 里加 `game: Option<GameLayer<'a>>`；Some 时 page/tabbar/fixed 为空页、不参与
```

- **缩放**：后备缓冲尺寸与输出像素尺寸常常不同（默认逻辑尺寸 = 输出的 1/dpr）。缩放规则是对齐判据的关键：
  - CPU 与 GPU 必须用**同一个整数定点算法**（16.16 定点坐标、整数权重的双线性），GPU 着色器 `textureLoad` 四个点手算权重，不用硬件采样器——这样延续「GPU 与 CPU 逐字节一致、阈值 0」。
  - 尺寸相同走 1:1 拷贝快路；整数倍放大可走最近邻快路**仅当** `filter == Nearest`。
  - 默认 `Bilinear`；取证确认微信放大时是否平滑（社区反馈 Android 上缩放发糊、不能设 `imageRendering`，倾向于双线性），以取证为准。
- **透明**：主画布默认不透明（2D 上下文清屏为透明时底色是黑还是白——取证确认）。WebGL `alpha:false` 默认。
- **覆盖层**：Toast / Loading / Modal / ActionSheet / 键盘上方的输入条 / 原生按钮 / 胶囊，复用 `OverlayRefs` 与 `TopBand`（胶囊画在右上角）。有覆盖层动画时走「直通帧」（与小程序一致）。
- **脏区**：2D 上下文每次光栅记录包围盒，帧末合并成 ≤ 8 个矩形交给 `LayerCanvas::write_rect`；GPU 只上传脏行。游戏常常每帧整屏清画，这时就是整张上传——这是 CPU 2D 的固有成本，§5.5 有预算。
- **上屏**：与小程序同一套 `engine_gpu::present_on` / `cpu::compose` / `pixels_into` / `BlitToWindow`，宿主侧代码不分叉。

### 5.5 CPU 2D 的性能预算（必须先量）

全屏后备缓冲 1080×2400 = 2.6M 像素，60fps 下整屏清 + 画 = 每秒 1.5 亿像素以上的写入，加上 GPU 上传每帧约 10MB。
默认尺寸是逻辑尺寸（约 393×873 = 0.34M 像素，dpr 2.75），成本低一个数量级。所以：

- G2 用 `examples/game_bench`（05 §5.3）在一加 PLY110 上量：逻辑尺寸与 ×dpr 尺寸两档、精灵数 100/500/1000/2000，出「每帧光栅 ms」与「上传 ms」。
- 结论写进 `doc/引擎测试说明.md`。若 ×dpr 档在 500 精灵下达不到 60fps，进入决策 D-6（GPU 加速 2D：wgpu 批量贴图 + 路径仍 CPU），**不在没有数据时开工**。

## 6. 二进制桥

### 6.1 现状的问题

参数与返回只能字符串（`register_function`），二进制一律 base64，而 base64 是纯 JS 逐字节实现（`codec.js`）。游戏的纹理上传、音频解码、文件读取、网络二进制、`getImageData` 都在热路径上。

### 6.2 设计

```rust
// src/js/binary.rs（新增，≤500 行）
pub enum JsArg<'js> { Str(String), Num(f64), Bool(bool), Bytes(BytesRef<'js>), Null, Undefined, Obj(Object<'js>) }
pub enum JsRet { Str(String), Num(f64), Bool(bool), Bytes(Vec<u8>), Null, Undefined, Json(serde_json::Value) }

impl JsRuntime {
    /// 参数按原类型交给 Rust；ArrayBuffer / TypedArray / DataView 以借用切片给出（调用期间有效，不拷贝）
    pub fn register_native<F>(&self, name: &str, f: F) where F: Fn(&Ctx, &[JsArg]) -> JsRet + 'static;
}
```

- rquickjs 0.12 的 `ArrayBuffer` / `TypedArray<T>` 读写接口在 G0.3 用探针核实（函数名与是否需要额外 feature **未核实**）。
- **借用期间不得回调 JS**（回调可能 detach/resize 这个 buffer），类型上用生命周期约束；需要跨帧保存就显式拷贝成 `Vec<u8>`。
- Rust→JS 返回 `Bytes` 时新建 `ArrayBuffer`（一次拷贝）；大块数据（解码后的图片、音频 PCM）不回 JS，留在原生侧，JS 只拿句柄（`Image`、`AudioBuffer` 是原生类）。
- 异步回包不再拼 JS 源码：在 JS 侧登记回调表（`__cb[id] = fn`），原生侧保存 `Persistent<Function>` 直接 `call((id, payload))`，payload 可以是 `ArrayBuffer`。这条路给游戏侧新代码用；小程序现有的 `format! + eval` 不动。
- 修 `call_function` 的转义（改用 serde_json 字面量）——这是安全修复，单独提交，对小程序是行为不变（现有调用点的参数里没有反斜杠与换行，04 G0.7 用测试证明）。
- 上限：单次过桥 ≤ 256MB（超出抛 `RangeError`），防止 OOM 时拷贝放大。

### 6.3 首批接到二进制桥的 API

`getImageData/putImageData`、`wx.getFileSystemManager().readFile/readFileSync/writeFile/appendFile/read/write`（ArrayBuffer 直通）、`wx.request`（`responseType:'arraybuffer'`、ArrayBuffer `data`）、`SocketTask.send/onMessage`、TCP/UDP、`WebAudioContext.decodeAudioData`、`TextEncoder/TextDecoder`、`wx.arrayBufferToBase64/base64ToArrayBuffer`（改成原生）、WebGL 的 `bufferData/texImage2D/readPixels/uniform*v`。

## 7. 输入

### 7.1 新 FFI

```c
// phase: 0 down, 1 move, 2 up, 3 cancel；id: 宿主的指针 id（Android pointerId、iOS 映射后的小整数、Flutter pointer）
// x, y: 逻辑像素（相对引擎视图左上角）；force: 0~1（没有就 0）；t_ms: 宿主单调钟毫秒（与 pump 同一时钟）
int mr_app_touch(MRApp*, int phase, int id, float x, float y, float force, double t_ms);
```

- 宿主**每个指针**一次调用；Android `ACTION_POINTER_DOWN/UP` 拆成对应指针的 down/up；`ACTION_MOVE` 对每个指针、每个历史采样（`getHistoricalX`）各一次（按时间顺序），引擎侧合并成一次 `touchmove`（见下）。
- 小程序实例也可以收 `mr_app_touch`：主指映射到现有 `pointer_*`、副指到 `pointer2`，行为与今天相同（宿主可以统一只调新接口，老接口保留）。这一点在 04 G3 单独验收。

### 7.2 事件语义（`src/game/touch.rs`）

- 事件：`touchstart`（有手指按下）、`touchmove`（有手指移动）、`touchend`（有手指抬起）、`touchcancel`（系统取消）。回调参数 `{touches, changedTouches, timeStamp}`。
- `Touch`：`identifier`、`screenX/screenY`、`clientX/clientY`、`pageX/pageY`（三者在小游戏里都等于视图内逻辑坐标——取证确认）、`force`。
- `identifier`：一次按下到抬起期间不变；**取证决定**是透传系统 id 还是从 0 起分配最小可用值（两者对游戏的差别：有的游戏把 identifier 当数组下标）。
- `touches`：事件发生后仍在屏幕上的全部触点（`touchend` 时不含抬起的那个）；`changedTouches`：本事件变化的触点。
- 同一 pump 内同一手指的多次 move：**不合并**还是**合并**取证决定；默认按浏览器做法每个宿主事件一次 `touchmove`（游戏的手势速度计算依赖采样密度）。为防止 1000Hz 触控采样淹没 JS，单帧单指最多派发 8 次 move，超出的合并到最后一次（保留最后坐标）——这条是保护措施，写进 06。
- 多指上限 10。超出的指针忽略（不派发），宿主日志一行。
- 进后台 / surface 丢失 / 来电：对所有按着的手指派发 `touchcancel`。

### 7.3 PC 输入

`wx.onKeyDown/onKeyUp`（`{key, code, timeStamp}`）、`wx.onMouseDown/onMouseUp`（`{button, x, y, timeStamp}`）、`wx.onMouseMove`（`{movementX, movementY, x, y, timeStamp}`——取证确认字段）、`wx.onWheel`（`{deltaX, deltaY, deltaZ, x, y, timeStamp}`）。
来源：桌面窗体（winit）与 macOS SDK；移动端外接键盘可选（Android `onKeyDown`）。复用现有 `mr_app_key` 与 `mr_app_wheel`，新增 `mr_app_mouse(phase, button, x, y, t_ms)`。

### 7.4 命中优先级

自上而下：系统级覆盖层（Modal / ActionSheet / Loading 带 mask）> 原生按钮（UserInfoButton 等）> 胶囊 > 游戏。
- Modal 弹着时游戏收不到任何触摸（与微信一致：模态）。
- 原生按钮：按下落在按钮上时，**按钮消费**，游戏收不到这次触摸序列——取证确认（G0.2）；若真机两边都收到，按真机。
- Toast 不拦截触摸（`mask:false`）；`mask:true` 拦截。

## 8. 音频

### 8.1 结构（`src/game/audio/`，小游戏专用；小程序的 `audio_ctx` 不动）

```text
 JS（InnerAudioContext / WebAudioContext，原生类）
        │  命令（无锁环形队列 SPSC：play/pause/seek/volume/param 自动化）
        ▼
 音频线程（cpal 输出回调，实时优先级）
   ├── Voice 表：每个 InnerAudioContext 一个 Voice（PCM 源 + 增益 + 速率 + 循环 + 起止）
   ├── WebAudio 图：节点按拓扑序每 128 帧渲染一块（render quantum，与 Web Audio 规范一致）
   └── 混音 → 输出（f32，设备采样率；源采样率不同的线性/多相重采样）
        ▲
 解码线程池：symphonia（mp3/aac/m4a/wav，另开 ogg/vorbis 决策 D-4b）；短音效整段解码进缓存；
            长音乐（> 10s 或 > 2MB）流式解码（环形缓冲 2s）
```

- **音频回调里禁止**：分配、加锁、I/O、日志（steering 30「热路径不分配」在这里是硬要求）。命令经 SPSC 队列，状态回报经另一条队列到引擎线程。
- 事件（`onCanplay/onPlay/onPause/onStop/onEnded/onTimeUpdate/onError/onWaiting/onSeeking/onSeeked`）在 pump 第 3 步派发。`currentTime` 取音频线程回报的**已播放帧数**，不再按 `Instant` 估算。
- 并发上限：Voice 32 个（可配）；超出时新的 `play()` 抢占最早开始且非 `loop` 的那个，并打日志——取证真机行为（微信对同时播放数有限制，具体数字**未核实**）。
- `obeyMuteSwitch`（iOS）：映射到 AVAudioSession 类别（遵守静音键 → `.ambient`，否则 `.playback`）；`wx.setInnerAudioOption({mixWithOther, obeyMuteSwitch, speakerOn})` 全局生效。
- 打断：来电 / 其他 App 抢焦点 → 暂停全部 Voice → `wx.onAudioInterruptionBegin`；结束 → `wx.onAudioInterruptionEnd`（**不自动恢复播放**，与微信一致——取证确认）。
- 前后台：`onHide` 暂停全部 Voice（记住状态），`onShow` 不自动恢复（取证确认；若微信自动恢复 BGM，按真机）。
- 输出设备丢失（耳机拔出、蓝牙断开）：cpal 报错 → 重新打开默认设备，最多 3 次；仍失败进入静音模式（时钟照走、事件照发），日志写明。

### 8.2 输出后端（决策 D-4）

推荐 cpal（rodio 底下就是它）：Android 走 AAudio（API 26+）/ OpenSL ES，iOS / macOS 走 CoreAudio。
要在 G0.3 探针里确认：cpal 在 `aarch64-linux-android` 与 `aarch64-apple-ios` 交叉编译通过、实测输出延迟与回调周期、体积增量。
备选：宿主桥接（Android `AudioTrack` low-latency / Oboe，iOS `AVAudioEngine`），引擎只产 PCM。

## 9. Worker

- `wx.createWorker(scriptPath, {useExperimentalWorker})`：新线程 + 新 `JsRuntime`（独立 Runtime 与 Context），只装 `core` 里的 worker 子集（console、timer、codec、fs 只读子集、`worker` 对象），**不装** canvas / 音频 / UI / 网络（以官方 Worker 可用 API 列表为准，G0.2 取证）。
- 同时最多一个（官方限制）；第二次创建前未 `terminate` 的，按真机行为（抛错或 fail，取证）。
- 消息：结构化克隆子集（基本类型、对象、数组、`ArrayBuffer`、TypedArray、`Date`、`Map/Set`）——在源 runtime 里序列化成自有二进制格式，跨线程用 `crossbeam_channel` 传 `Vec<u8>`，目标 runtime 反序列化；循环引用报错（`DataCloneError`）。`transfer` 参数暂按拷贝实现，语义上让源 ArrayBuffer 变 detached（`byteLength=0`），与规范一致。
- 主线程侧 `worker.onMessage` 在 pump 第 3 步派发；worker 线程自己有事件循环（定时器 + 消息），空闲时阻塞在 channel 上，不轮询。
- `terminate()`：设中断标志（interrupt handler 返回 true）→ 线程退出 → 释放 runtime；`onProcessKilled` 在 worker 线程 panic 或被守护中断时触发。
- 进程级静态状态（01 §1.9）：worker 只用不带全局表的模块；fs 走纯函数版本（不碰 fd 表），G6 前把 `wxfs` 的 fd 表改成按 runtime 持有。

## 10. WebGL 路线（决策 D-2）

| 方案 | 做法 | 优点 | 风险 / 代价 |
|---|---|---|---|
| **A. ANGLE（推荐）** | 各平台链接 ANGLE（`libEGL`/`libGLESv2`），用 `EGL_ANGLE_create_context_webgl_compatibility` 建 **WebGL 兼容上下文**；JS 侧原生类逐个绑 GL 调用 | ANGLE 自带 WebGL 校验与 GLSL ES 翻译（Chrome 同款），安全边界由它守；iOS 走 Metal 后端、Android 走 Vulkan 或系统 GLES 后端、macOS 走 Metal | 体积（每 ABI 数 MB，G0.3 实测，超 8MB 停下来问用户——沿用 GPU 设计的 D2.4 口径）；ANGLE 构建链（gn/ninja）进 CI；与 wgpu 合成器共用一块 surface 要设计（下） |
| B. 系统 GLES + 自写校验 | Android 直接用 EGL + 系统驱动；iOS 只能 ANGLE（GLES 已弃用） | Android 体积为 0 | WebGL 校验（越界、类型、状态、扩展门控）要自己写，工作量与安全风险都大；驱动差异直接暴露给游戏 |
| C. WebGL → wgpu 翻译 | 用 naga 把 GLSL ES 转 WGSL，自己模拟 GL 状态机 | 与现有 wgpu 合成器同栈 | naga 的 GLSL 前端面向桌面 GLSL 4.x，对 GLSL ES 1.00 / 3.00 的覆盖不足（风险高，未核实具体缺口）；GL 状态机模拟工作量极大 |

推荐 A 的集成要点（详细设计在 G8 开工前单独出 `design-webgl.md` 并评审）：

- **surface 归属**：主画布是 WebGL 时，EGL surface 建在宿主同一个 `ANativeWindow` / `CAMetalLayer` 上，wgpu 合成器**不再**挂这块 surface。覆盖层（Toast/Modal/按钮/胶囊）在 GL 里画：CPU 光栅出一张覆盖层 RGBA 纹理，帧末用一个固定着色器 blend 到默认帧缓冲上，再 `eglSwapBuffers`。
- **与合成后端解耦（11 B-3）**：WebGL 可用与否只看 ANGLE 能否建 WebGL 兼容上下文，**与合成器是 CPU 还是 GPU 无关**。硬件后端建不了时走 ANGLE + SwiftShader（D-2b 必做），`getContext('webgl')` 不返回 `null`。WebGL 的逐字节基线用 SwiftShader（确定性），硬件 GPU 按阈值比。
- **微信扩展 `wxBindCanvasTexture`**（11 B-4）与 **WebGPU `wx.getGPU`**（11 B-5，映射到 wgpu）在 G8 一并做。
- **运行中 GPU 丢失**：派发 `webglcontextlost`（canvas 事件，`preventDefault` 后可恢复）→ 重建上下文 → `webglcontextrestored`。游戏不处理就是黑屏，这与浏览器一致；引擎层面不崩。
- **离屏 WebGL**：离屏画布上的 WebGL 用 pbuffer surface；`drawImage(webglCanvas)` 到 2D 要 `readPixels`（慢路径，日志提示一次）。
- **`texImage2D` 来源**：`Image`（原生已解码 RGBA，直接上传，处理 `UNPACK_FLIP_Y_WEBGL`、`UNPACK_PREMULTIPLY_ALPHA_WEBGL`、`UNPACK_COLORSPACE_CONVERSION_WEBGL`）、2D 画布、`ImageData`、TypedArray。
- **压缩纹理**：按设备暴露 `WEBGL_compressed_texture_etc`/`etc1`/`astc`/`pvrtc`/`s3tc`，由 ANGLE 能力决定。
- **扩展清单**与 `getParameter` 返回值写进 G8 设计，取证真机常见值（`MAX_TEXTURE_SIZE` 等）。

## 11. 线程模型

```text
 宿主 UI 线程 ──(post)──► 引擎线程（Android HandlerThread / iOS MiniEngineThread / 桌面主线程）
                            │  所有 mr_app_*、QuickJS、2D 光栅、合成、GPU 提交、WebGL 调用
                            │
       ┌────────────────────┼─────────────────────┬────────────────────┐
  解码线程池（图片 2）   网络线程（每请求 / 每连接）   音频线程（实时）     Worker 线程（≤1）
       │ 完成队列            │ DONE 队列（按 owner）     │ SPSC 状态回报        │ channel
       └────────────────────┴──────► 引擎线程 pump 第 3 步取回 ◄──────────────┘
```

- QuickJS 只在引擎线程（以及 Worker 自己的线程）上碰，`Rc` 闭包天然防止跨线程误用。
- WebGL 上下文绑定在引擎线程（`eglMakeCurrent` 一次，不换线程）。
