## 为什么 Android 不用 cpal
cpal 在 Android 上直接链接 libaaudio（API 26 起才有），工程 minSdk 是 24：链接报 `unable to find library -laaudio`，
即使链上，Android 7.x 上整个库加载失败。改成 `aaudio.rs` 运行时 `dlopen("libaaudio.so")`，找不到就走静音模式。
API 24/25 上目前**没有声音**（没有 OpenSL ES 后备），记下。
## G5.3 WebAudio（`src/game/audio/graph`、`src/game/audio/web`、`game-webaudio.js`）
- 分工：引擎线程留一份图的镜像（节点、连线、每个参数的时间线），算好每个上下文的拓扑序，连同建好的节点（缓冲在引擎线程分配）
  经命令队列发给音频线程；音频线程按 128 帧的量子逐节点处理，与 InnerAudio 的 Voice 叠在同一个输出上，只换表、不分配；
- 真做的节点：BufferSource、Oscillator（按 Chrome 的 PeriodicWave：4096 点、36 个音区限带）、ConstantSource、Gain、Delay、
  BiquadFilter（8 种）、IIRFilter、WaveShaper、Panner（equalpower、三种距离模型、锥形）、ChannelMerger / Splitter、Analyser
  （Blackman 窗、平滑、dB / 字节换算）；AudioParam 全部自动化方法（含 cancelAndHoldAtTime）、a / k-rate、节点接参数（FM）；
  混音规则按规范的 speakers / discrete 表；`decodeAudioData` 在后台线程解、重采样到上下文采样率；
- 寿命：JS 对象回收（FinalizationRegistry）且没有活着的上游才拿掉；播完的源断开出边、放掉槽位；有尾巴的节点（Delay / Biquad / IIR）
  上游没了之后放完尾巴再拿掉。wa4：200 个「源 → 匿名 gain → destination」播完 + GC 后原生只剩 destination；
- 小程序不受影响：仍用 `webaudio.js`（出声走 InnerAudioContext）；`game-audio` 没编进去时小游戏也退回那一份；
- 命令队列满了从前直接丢一条（日志一行），现在按顺序排进 backlog、下一帧再发（InnerAudio 同样受益）。

### 对拍时找到并改掉的
- **Delay 的帧数要按 f32 算**：0.01 × 48000 在 f64 里是 479.99999，线性插值漏进相邻样本一点点；Chrome 用 f32，正好 480。改完该段 8e-6 → 2.4e-7；
- **源播完之后输出要关掉**（下游看到 1 声道静音）：Chrome 的 BufferSource 放完就关输出，Delay 的立体声尾巴因此下混成单声道；
  正好在量子末尾放到头的那一下也算播完；
- **m4a 的编码器预滚帧**：symphonia 的 isomp4 读取器不看编辑表（`elst`），1 秒的 m4a 解出 49152 帧、整体偏 1024 帧；
  按编辑表裁掉（`audio_ctx/mp4_edit.rs`，小程序 InnerAudio 同样受益）。mp3 / ogg 的延迟与填充 symphonia 的解码器已经按包裁过，再裁会少 478 帧；
- 夹具里拆分 / 合并节点要拿住引用：只被局部变量引用的节点 GC 之后，上游一播完原生就把它们拿掉，Delay 的尾巴随之变成单声道；
  两边什么时候 GC 不确定，对拍不能依赖它。

### 与 Chrome 已知的差别（记下，不假装一致）
- **开始于量子中间的振荡器**：Chrome 在开始的那个量子里按量子开头读频率参数（输出第 offset+j 帧用第 j 帧的频率）；
  规范与引擎按帧自己的时刻读。FM 时第一个量子之后相位就差开（实测 1.25s 起播的 FM 与 Chrome 差 0.15）。夹具的段边界对齐量子避开它；
- **环**：环上的边读源节点上一个量子的输出。规范要求环里必须有 DelayNode、延迟钳到 ≥ 128 帧且不额外加；这里带 Delay 的反馈环总延迟多 128 帧，
  没有 Delay 的环也照常算（规范要求静音）；
- 降级：DynamicsCompressor 直通、ScriptProcessor 静音且 onaudioprocess 不触发、WaveShaper 的 2x / 4x 按 none、Panner 的 HRTF 按 equalpower；
  `decodeAudioData` 重采样用线性插值（Chrome 是 sinc）；Delay 只存两个声道；子样本精度的起点没做。

## G5.5 打断与会话（`src/game/audio/session.rs`、`GameAudioSession.kt`、`GameAudioSession.swift`）
- 引擎：宿主调 `mr_game_audio_interruption(1)` → 在播的 InnerAudio 发 `pause`、混音器挂起、running 的 WebAudioContext 变成
  `suspended`（发 statechange），**然后**派发 `wx.onAudioInterruptionBegin`（回调里读到的已经是暂停后的状态）；打断期间 `play()`
  不生效、`ctx.resume()` 以 InvalidStateError 拒绝；`(0)` → 派发 `wx.onAudioInterruptionEnd`，不自动续播。重复的开始 / 结束不再派发；
- `wx.setInnerAudioOption({mixWithOther, obeyMuteSwitch, speakerOn})`：只认布尔值（非布尔忽略），默认三项都是 true；
  改过就发宿主事件 `{"type":"audioSession",…}`；
- Android：`mixWithOther: false` 申请独占焦点 `AUDIOFOCUS_GAIN`（USAGE_GAME），`LOSS` / `LOSS_TRANSIENT` = 打断开始、`GAIN` = 结束，
  `LOSS_TRANSIENT_CAN_DUCK` 交给系统压音量；`true`（默认）不抢焦点。来电靠音频模式（RINGTONE / IN_CALL / IN_COMMUNICATION），
  API 31+ 用监听、更早的每秒查一次，不要电话权限。切后台放掉焦点、回前台重新申请；`obeyMuteSwitch` / `speakerOn` 在 Android 上没有对应，只记下；
- iOS：`obeyMuteSwitch` 决定类别（true → ambient，false → playback）、`mixWithOther` 决定 `.mixWithOthers`；
  `interruptionNotification` → `mr_game_audio_interruption`。iOS 还没有小游戏视图（G2.8），这个类只做了
  `swiftc -typecheck`（iOS 13 / arm64），没有真机。

### 真机（一加 PLY110，`g-audio?mix=0&resume=1`）
- 启动：`audioSession {mixWithOther:false}` → 「申请独占音频焦点：拿到」 → `bgm.Play`；
- adb `KEYCODE_MEDIA_PLAY` 让酷狗在后台开播 → 焦点 `-1`（AUDIOFOCUS_LOSS）→ 「音频被系统打断：全部暂停」→ `bgm.Pause` →
  `interruptBegin {bgmPaused:true}`（顺序与 au8 一致）；
- 酷狗暂停之后系统**不会**把焦点还回来（永久 LOSS 没有 GAIN），打断一直持续；切后台再回前台 → 重新申请拿到 →
  `interruptEnd {bgmPaused:true}` → 夹具在回调里 `bgm.play()` → `bgm.Play`。后台期间不派发 End（否则游戏在 End 里 play，在后台就响了）；
- 来电路径：这台 ROM 没有 `cmd audio`，adb 造不出通话模式，要真打一个电话（手测清单 M-A 系列）。
