# G2 验收记录（进行中，2026-10-27，分支 `feat/mini-game`）
机器：Apple M3 Pro（桌面）、一加 PLY110（Android 16 / API 36，物理 1272×2772，游戏逻辑 427×931@2.975，显示 60Hz）。
真机库：`tools/build-android-abi.sh arm64-v8a`（MOBILE_LTO 默认关，与发布的 thin LTO 库不同，数字偏保守）。

## 真机数字（一加 PLY110，CPU 后端）
| 场景 | 屏上重复（按 60fps） | rAF dt 中位 / 峰值 | 引擎工作中位 / p99 / 最大 | 引擎 >8ms |
|---|---|---|---|---|
| `g-square` 空载 | 0 / 662 | 16.59 / 16.59ms | 3.5 / 6.1 / 8.3ms | 2 / 715 |
| `g-bench-rects?n=500` 逻辑尺寸 | 0~1 / ~700（≤0.1%） | 16.59 / 16.59ms | 8.6 / 11.4 / 13.3ms | 483 / 769 |
| `g-bench-rects?n=500&dpr=1`（×dpr，D-6 依据） | 2 / 660（0.3%） | 16.59 / 16.59ms | 10.2 / 13.7 / 15.2ms | 689 / 715 |

`g-bench-rects` 不是 05 §5.2 的门槛夹具（门槛用 `g-bench-sprites`，等 G4 的 Image）。它的引擎 >8ms 帧远超 1%：
rAF 回调本身 6.4ms/帧（夹具自报 `jsMsPerFrame`），simpleperf 里 QuickJS 解释执行（`JS_CallInternal` 等）与绘制大致对半。
继续压要么换 JS 引擎（D-3），要么等 GPU 游戏层（G2.5）。

### 优化过程（同一夹具，逐步）
| 改动 | 桌面 pump 中位 | 真机引擎工作中位 | 像素 |
|---|---|---|---|
| 起点（fillRect 走通用 `fill_path`） | 2.28ms | 10.8ms | — |
| 轴对齐矩形抗锯齿特化（`canvas/rect_aa.rs`） | 1.25ms | 9.9ms | 第 90 帧快照 md5 不变 |
| 不建 Path 直填四边形、只逐像素算边缘列、fillStyle 惰性规范化 | 0.61ms | 8.6ms | 同上 |

等价判据：`rect_aa_tests` 两组随机用例（6000 例含 1/8 网格边界、3000 例含旋转 / 退化 / 平移 / 裁剪）与通用路径逐字节相同；
故意改坏边界条件（`<=` → `<`）与整格 alpha 时测试会失败（防空转已验过）。

## 小程序不回退
- `game-equiv.sh`：快照 21/21、damage、gallery、tabBar、SDK 一致性全部一致。交互一步在 showcase 页 GIF 区（包围盒 x[616,698]）
  报 0.25~0.30% 差异，每次落在不同用例上，是已知的 GIF 墙上时钟噪声（steering 30）。
- 真机小程序顿挫（原生示例）：`query-slow` 0.4%（清单 0.4~0.6%）；`query-fastslow` 2.3%，清单记的是 1.5%。
  同一台手机、同一天，把引擎库换成 main `a950b9a` 编出来的那份复测是 **2.2%**，说明这不是本分支引入的回退，是当天设备状态。

## 踩到的坑（写给后来的人）
- **rAF 相位漂移**：真机 vsync 周期 16.59ms，不是 16.67。按理想 60fps 间隔累加会每 3.85s 跳过一个 vsync（屏上一次 33ms）。
  现在显示周期 ≈ 目标/k（误差 5% 内）时按 vsync 计数锁相，见 `game/raf_pacer.rs` 文件头。
- **APK 里打进旧库**：引擎库、`gradlew assembleRelease`、装包必须在**同一条命令里**依次执行，分开调用时实测装进去的是上一版
  （`android-game-jank.sh install` 会比对 APK 与 jniLibs 的 md5，不一致就拒绝量）。
- simpleperf 的 `-t` 要传 `ps -T` 第三列（TID）；传错时 `record` 报错但旧的 `perf.data` 还在，`report` 出来是上一次的数据。
