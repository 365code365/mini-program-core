# G9 验收记录（2026-10-28，分支 `feat/mini-game`）

复现：`bash tools/fetch-engines.sh && cargo test --release --test game_e2e -- e1_ e2_ e3_ e4_ od pc1`；
长稳 `cargo run --release --example game_soak -- <包> 30 type=webgl`（桌面）、`bash tools/android-game-soak.sh e-phaser 30 type=webgl`（真机）。

## 决策

| 编号 | 定为 | 理由 / 影响 |
|---|---|---|
| D-3 JS 引擎 | **A：保持 QuickJS** | V8 + JSC 两套引擎的绑定与回归是单独一期的工作量；按 06 的约定写明：**C2 层（JS 语言与内置对象）不是 100%** —— 没有 JIT、`Intl` 只有最小实现（Segmenter / NumberFormat / DateTimeFormat / Collator / PluralRules 的常见用法，G9.1 实测 PixiJS 加载即依赖它）。e-phaser 真机 >8ms 帧 3% 的那部分在 JS 执行上 |
| D-6 GPU 加速 2D | **不做** | 三个引擎的 Canvas / WebGL 渲染器真机都贴 60fps（下表）；做了 2D 两个后端的像素就会分叉 |

## G9.7 开放数据域

| 判据 | 结果 |
|---|---|
| 独立 JS 环境 | 第二个 QuickJS 运行时；主域的全局看不到；`wx.request` / 存储 / WebGL 都没有（OD1） |
| sharedCanvas | 主域 `getOpenDataContext().canvas` 与开放数据域 `wx.getSharedCanvas()` 是原生表里同一块；主域只能 drawImage 它，`getContext` → null、`toDataURL` 抛错（OD1） |
| 消息 | 单向 postMessage（JSON），下一帧投递；开放数据域的定时器 / rAF 随主域帧推进，在主域 rAF 之前画 |
| 关系链 API | `hostApis` 点名 `openData.getFriendCloudStorage` 等才交宿主（hostCall，编号从 1<<24 起）；没点名 fail（OD2：宿主回两条好友数据，排行条按分数画出） |
