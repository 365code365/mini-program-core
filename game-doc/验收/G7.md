## 真机数字（一加 PLY110）
| 场景 | 数字 |
|---|---|
| 传感器 `game` 档 | 49~51Hz。注册之后约 5s 才来第一个采样：在主 looper 上注册、按微秒给周期都一样，属于系统 / HAL 行为 |
| `g-video` 事件 | play → 每秒一次 timeUpdate（位置连续，loop 回到 0）→ 3s pause → 4s play → 7s destroy，时刻与夹具定的一致 |
| `g-video` 画面 | 视频框内 6 万多种颜色（真在播），框外是游戏底色 (32, 48, 64)，视频盖在游戏上面 |
| `g-video` 顿挫 | 60Hz，屏上 291 帧，重复 0 次；引擎工作中位 2.50ms、p99 5.20ms、最长 5.50ms，>8ms 0 / 343 |

修过的一处：`play()` 常在视频 prepared 之前调，那时 `isPlaying` 还是 false，第一版 timeUpdate 的计时器因此停掉，要等 pause 之后再 play 才有。现在按「要播」标志走，没播起来时只跳过不发。

## 待取证 / 取舍
- 键盘输入条的样式：照微信的白底 + 绿色确认键画了个大概，没取证。
- 原生按钮的按压态：没做。
- GameClub 按钮的图标：没有素材，只画底色与文字。
- 视频 `underGameView`：引擎上屏是不透明的 Surface，视频透不上来，Android 一律盖在游戏上面。
- 视频 `objectFit`：VideoView 只有 contain，cover / fill 没做；`requestFullScreen` 铺满宿主视图，不转屏。
- 代理对象的 `canIUse`：现在按「对象在」回答，宿主没接的也报 true，待对照微信。
- iOS：小游戏视图没做（G2.8），键盘、按钮、传感器、视频的 iOS 宿主都还没有。
