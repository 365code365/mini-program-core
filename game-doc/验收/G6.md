## 取舍与已知差别（记下，不假装一致）
- 主画布不跟着窗口改尺寸：与微信一样，游戏在 onWindowResize 里自己改 canvas.width / height；改之前系统缩放铺满；
- 引擎内旋转多一次整帧转置（Android 上屏走转好的 RGBA，不走直写），只在横屏嵌竖屏页面这种少见场景用；
- Worker 的 onMessage 参数是消息本身（与小程序那份一致），官方文档写的是 `res.message`，**真机形状待取证**；
- Worker 活着的时候宿主每帧都要来（主线程要取 Worker 的消息）；没有消息时这一帧几乎不花时间；
- 02 §9 写的「wxfs 的 fd 表改成按 runtime 持有」没做：Worker 里不装 fs，碰不到那张表；
- 插件的 `contexts` 只解析不限制（开放数据域 G9.7 还没做）。
