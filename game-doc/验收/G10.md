# G10 验收记录（2026-10-28，分支 `feat/mini-game`）

复现：`cargo test --release --test game_e2e -- wasm`；真机 `am start -n dev.minirender.example/.GameActivity --es game g-wasm`。

## D-11 定为：wasmi 一条路（全平台）

计划里是 wasmi（iOS）+ Wasmtime JIT（Android / 桌面）。这一期只做 wasmi：

- wasmi 已经比 QuickJS 跑同一算法快 3~9 倍（下表），而 QuickJS 本身没有 JIT —— 游戏里瓶颈先在 JS 那边；
- Wasmtime 进 Android 要多带一份 Cranelift（体积 10MB 量级，超 8MB 预算），还要处理 W^X 内存与 Android 的 SELinux 策略；
- 执行引擎在 `game/wasm` 里只经 `wasmi::{Engine, Store, Func, Memory…}` 一层，换引擎时改动面在这一个目录。

## 取舍

- 内存不用 rquickjs 的 `ArrayBuffer::from_source`：它的释放回调在 detach 与回收时各跑一次（QuickJS 的 finalizer 不看 detached），实测重复释放直接 abort；这里建不带释放回调的外部 ArrayBuffer；
- wasm 死循环不受 JS 看门狗管（QuickJS 的中断回调只在 JS 字节码里检查）；
- externref 的 JS 值按编号存在 JS 侧表里，不回收。
