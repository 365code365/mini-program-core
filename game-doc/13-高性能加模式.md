# 13 高性能+ 模式（`iOSHighPerformance+`）

## 为什么要有

| 模式 | 游戏 JS | 画 | 萌宠小岛（iPhone 16 Pro Max） |
|---|---|---|---|
| 普通（`native`） | QuickJS（没有 JIT） | 引擎 GL → ANGLE → Metal | 60fps，JS pump 8~16ms |
| 高性能（`web`） | WKWebView（JSC JIT） | WebKit 自己的 WebGL / Canvas | ~38fps（WebKit 的 GL 路径慢） |
| 高性能+（`plus`） | WKWebView（JSC JIT） | 每帧录下画布 / WebGL 调用交回 App，引擎在 ANGLE 上回放 | ~60fps，页面 JS ~2ms/帧 |

高性能+ 同时拿到 JIT 与引擎自己的 GL 路径。

## 怎么选

- game.json `"iOSHighPerformance+": true` → 高性能+；`"iOSHighPerformance": true` → 高性能；都没有 → 普通。
- iOS 启动参数 `-gameMode web|plus|native` 覆盖 game.json。
- 带 `openDataContext` 或 `plugins` 的包回退普通模式（这两样在页面侧没实现）。

## 结构

```
WKWebView（透明，盖在上面收触摸）                App 进程
  game.js + weapp-adapter                          GameEngine(remote=true)：不跑 game.js
  game-canvas / game-webgl*.js（与普通模式同一份）     ↑ mr_game_replay(bytes)
  wg-remote.js：把 __game_gl / __game_2d /             按 FNS 表调同一批原生 JS 函数
    __game_canvas_* / __game_img_* 换成二进制录制器 ──→   → ANGLE → CAMetalLayer（WebGamePlusRenderer）
```

- **编码**（`src/game/remote/wire.rs`）：调用头 `u8 fn | u8 flags(1=同步) | u16 argc`，参数带类型标签
  （undef/null/bool/f64/i32/string/typed array 带元素类型/array/JSON）。
- **对象编号**：页面自己发号（从 `0x6A5A0000` 起），作为创建类调用的最后一个参数带过去；原生侧按
  (上下文, 页面号) → GL 名映射，反查按 (上下文, 种类, 名) —— GL 名按类型各自编号，只按名会撞。
  不去猜 ANGLE 的分配顺序。
- **同步查询**：先把攒着的包冲掉再同步调一次（iOS `prompt('__wgr', b64)`，桌面同步 XHR `/__wg/rcall`）。
- **缓存，稳态帧零往返**：建上下文时 `__wgrBatch` 一次取齐 getParameter 常量、扩展列表（去掉
  `KHR_parallel_shader_compile`）、精度格式；link 之后 `__wgrProgramInfo` 一次取齐链接状态、日志、
  uniform / attrib 位置；measureText 按 字体+对齐+基线+文本 缓存。
- **流控**：最多 2 帧在途；原生回放到帧尾回 `__wgrAck()`；500ms 收不到就复位，不会卡死。
- **页面侧的坑**：GameGlobal 的 Proxy 目标必须是空的 null 原型对象（拿 window 做目标会违反 Proxy
  不变式，写 `document` 抛错）；GameGlobal 上藏掉 add/removeEventListener / dispatchEvent（微信没有，
  留着 weapp-adapter 会把普通对象派给原生 dispatchEvent → TypeError）。

## 真机数字（iPhone 16 Pro Max，`tools/ios-game-sweep.sh 40`，2026-10-31 背靠背）

| 游戏 | 普通 fps 中位 / 最低 | 高性能+ fps 中位 / 最低 | 高性能+ 原生侧掉帧（40s） |
|---|---|---|---|
| play-3d-island | 59.5 / 58.0 | 59.5 / 43.3（启动段） | — |
| play-3d-bowling | 60.0 / 59.5 | 60.0 / 58.8 | 8 |
| play-3d-runner | 60.0 / 60.0 | 60.0 / 55.6 | 44 |
| farm001（Cocos + wasm） | 60.0 / 60.0 | 60.0 / 41.8（启动段） | 7 |

高性能模式（`web`）在 island / farm001 上是 38 / 42fps，见 [12](12-高性能模式.md)。

读数注意：

- sweep 汇总把页面侧（行尾「（高性能模式）」）与原生侧的行混在一起算掉帧；只看原生侧要按行尾分开。
- 原生侧的「pump」在高性能+ 里是一次回放的耗时，稳态 ~15ms：ANGLE 在上一帧 drawable 没还回来时会在
  第一个 GL 调用上等，算进了回放时间，不是回放本身的计算量（普通模式 bowling 的 pump 也是 16.5ms）。
- 原生侧帧间隔按「回放完成的时刻」记，不是 vsync 时刻，抖一点就记一次掉帧，比普通模式的口径严。
- 最低 fps 出现在头几秒（加载资源、编 shader），稳态不掉。
