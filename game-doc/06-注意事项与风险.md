## 3. 注意事项（已知坑与易错点）

### 3.1 帧与节拍

1. **60fps 是对齐点**：官方 rAF 默认 60、上限 60。不要因为设备 120Hz 就跑 120（游戏逻辑按 60 写的会快一倍，例如按帧计时的动画）。
2. **90Hz 屏上 60fps 必然不均匀**（1、2 个周期交替）。必须让宿主把显示刷新率请求到 60/120（02 §4.2）；请求不到要在日志与判据里如实写。
3. **rAF 时间戳要用 vsync 时刻，不是回调执行时刻**：用执行时刻的话，动画每帧位移忽大忽小（小程序侧 `frame_clock.rs` 头注释记过同一个坑）。
4. **Android tick 开头预约下一个 vsync**（`EngineCore.tick`，避坑清单第 16 条）：游戏模式沿用，不要回退到「最后才挂」。
5. **后台恢复不要补帧、不要补定时器**：一口气补跑几百个 `setInterval` 会让回前台第一秒卡死。
6. **`FRAME_WANTS_MORE` 不要因为「有音频在播」就每帧置位**：音频在独立线程上，引擎只需 4Hz 派发 `timeUpdate`；每帧置位会让静止画面的游戏也满帧耗电。
7. 无头模式的帧时钟是确定序列，**真机不是**：只在无头里断言「恰好 N 次」，真机只断言间隔分布。

### 3.2 画布与合成

8. **主画布显示区不随 `width/height` 变**：改 `canvas.width` 只改分辨率，显示仍铺满窗口。
9. **缩放算法两端必须同一份整数定点实现**，否则「GPU 与 CPU 0 差异」守不住；GPU 着色器里不要用硬件采样器做双线性。
10. **非预乘 alpha**：引擎内部 RGBA8 非预乘（`canvas/mod.rs` 有断言），`getImageData` 直接给出即可；WebGL `UNPACK_PREMULTIPLY_ALPHA_WEBGL` 要在上传时转换，别把转换放进 2D 路径。
11. **不要把游戏画布放进进程级 `CANVAS_MANAGER`**：小程序与游戏会互相看见（`manager.rs` 头注释已记过），而且 2d 日志 50 000 条上限会让每帧整屏重画的游戏很快打满。
12. **立即模式下 `getImageData` 不需要 flush**：小程序那条路要先 `flush_canvas`，游戏这条路调用返回时像素已写好。不要照抄 flush 逻辑。
13. **画布对象被 GC 时释放后备缓冲**：一个 4096² 的离屏画布是 64MB，泄漏几个就 OOM。finalizer 必须测（GT-S5 同类用例）。
14. **`drawImage` 用 Image 句柄，不要用路径字符串缓存**：同一路径的图被重新加载（`src` 改了又改回）时，以句柄为准。

### 3.3 输入

15. **`--click` 绕过指针层的教训**（steering 30）：游戏的点击类回归只认真实指针序列（`mr_app_touch` / `--touch` / `--multitouch`），不要新增绕过状态机的测试入口。
16. Android `MotionEvent` 的 `ACTION_MOVE` 一次带所有指针、还带历史采样；只取 `getX(0)` 是常见错误（多指只剩一根）。
17. iOS `UITouch` 对象在一次触摸期间复用同一个实例，用 `ObjectIdentifier` 映射 id；`touchesEnded` 之后立刻释放映射，否则 id 会耗尽或复用错乱。
18. `identifier` 规律以取证为准；有的游戏拿它当数组下标，给系统原始 id（可能很大）会让这类游戏越界。
19. 进后台时必须给按着的手指发 `touchcancel`，否则回来后游戏里一直认为有手指按着（虚拟摇杆卡住）。

### 3.4 音频

20. **音频回调里不分配、不加锁、不打日志**。日志用计数器，在引擎线程上汇总打印。
21. 长音乐不要整段解码（现有 `audio_ctx` 整段解码成 f32：3 分钟立体声 44.1kHz ≈ 63MB）。
22. iOS 静音键：`obeyMuteSwitch` 默认值以取证为准；类别切换要在音频会话非激活时做，否则可能打断其他 App 的音频。
23. Android 音频焦点：游戏切后台要放焦点，否则用户的音乐 App 回不来。
24. 蓝牙耳机的输出延迟（150~300ms）不可控，延迟判据只用有线 / 扬声器。

### 3.5 内存与资源

25. QuickJS 的 GC 是引用计数 + 循环回收：持有原生对象的 JS 类（Image、Canvas、AudioBuffer、WebGL 对象）**必须**实现 finalizer，且 finalizer 里不能回调 JS。
26. `ImageStore` 淘汰只淘汰无引用条目（02 §5.3）；预算压力下宁可发 `memoryWarning` 也不让 `drawImage` 画空。
27. Android `onTrimMemory` 要接到 `memoryWarning` + GC + 清解码缓存；iOS 的内存警告同理。
28. 每个 `ArrayBuffer` 过桥的拷贝都要算进内存峰值：大块数据留在原生侧，JS 只拿句柄。

### 3.6 线程与生命周期

29. `register_function` 的闭包是 `Rc`（!Send）：Worker 的 runtime 必须在 Worker 自己的线程上创建并注册，不能主线程建好再移过去。
30. 进程级静态表（websocket、net_socket、wxfs fd、`APP_ROOT`）在 Worker 里不能用；Worker 只装不碰这些表的模块（02 §9）。
31. SDK「一个进程同一时刻一个引擎实例」的约束对游戏同样成立（`EngineTeardown.awaitPrevious`）：小程序打开游戏要先销毁小程序实例，或者走独立进程（宿主自己决定，集成指南写明）。
32. `surfaceGone` 要同步等引擎线程放手（`EngineCore.surfaceGone`）。WebGL 时 EGL surface 也必须在这一步销毁，否则 Android 上会出现 `BufferQueue has been abandoned` 一类错误。

### 3.7 生产健壮性（第二轮审查补充，见 09）

33. **panic 不能穿过 FFI**：游戏实例每个入口都要 `catch_unwind`；捕获后实例作废，不在同一实例上继续跑。Mutex 中毒之后 `lock().unwrap()` 会连环 panic，所以「捕获后继续」不可行。
34. **外部输入不 `unwrap`**：JS 传来的数值、宿主传来的指针 id、文件内容、网络回包，一律校验后再用。
35. **数据按 `appId` 隔离**，不按目录名（小程序现有路径按目录名，游戏不沿用）。
36. **`platform` 不能是 `devtools`**：游戏引擎会因此走调试分支。
37. **包装头与源码同一行**：`game.js` 与模块的包装函数头不能单独占一行，否则异常栈行号全部错一行，开发者按栈找不到代码。
38. **日志限流**：每帧最多 500 行，否则序列化日志本身造成掉帧，logcat 还会因量大整段静默。
39. **诊断开关先判再拼字符串**：`MINI_RAF_LOG` 等关着时零开销（热路径不分配）。
40. **相对路径的基准**：`Image.src`、`InnerAudioContext.src`、`loadFont` 的相对路径按包根还是当前模块解析，以取证为准；同一规则在三类资源上必须一致。
41. **屏幕常亮**：游戏是否默认常亮以取证为准；不常亮的话只看动画不触摸会被系统熄屏。
42. **没有调试器**：QuickJS 没有远程调试，也不支持 source map。集成指南要写明排查手段（日志开关、`mr_app_eval`），release 宿主可以关掉 `mr_app_eval`。
43. **构建矩阵**：默认、无 GPU、无 `game` 三种构建都要能编；后两种跑小程序全量回归，必须逐字节不变。

### 3.8 测试

44. 跑快照前清两处 storage（steering 30），游戏实例另清 `target/game-data/`。
45. 带墙上时钟的用例（守护超时、Worker 死算、真机节拍）只做日志 / 分布断言，不比跨运行像素。
46. 截图刚写出来本工具常要等约 1 分钟才读得到：能用 md5 / 像素统计判的就别看图（steering 30）。
47. 真机结论一律附 APK 里引擎库 md5 = jniLibs 那份（`android-jank.sh install` 已检查）。

## 5. 安全

1. **代码只在 QuickJS 沙盒里跑**：不提供 `eval` 以外的动态代码入口（`new Function` 由 QuickJS 本身提供，不额外开放）；不暴露任何宿主文件系统路径。
2. **路径**：只认 `wxfile://` 与代码包相对路径；拒绝 `..`、绝对路径、符号链接逃逸（`wxfs` 现有规则，补一条：解析后的真实路径必须在沙盒根下，用 `canonicalize` 校验）。
3. **原生回调不拼 JS 源码**：游戏侧新代码一律用 `Persistent<Function>` 直接调用（02 §6.2）；`call_function` 的转义 bug 在 G0.7 修掉。
4. **资源上限**：JS 内存、单次过桥、画布尺寸、状态栈深度、Image 预算、Voice 数、Worker 数、文件配额、storage 上限、触点数——每一个都有上限且有用例。
5. **WebGL**：只通过 ANGLE 的 WebGL 兼容上下文访问 GPU（越界与非法参数由 ANGLE 拦截）；不暴露原生 GL 扩展里与 WebGL 无关的部分；`WEBGL_debug_renderer_info` 默认不暴露（避免设备指纹——取证微信是否暴露）。
6. **网络**：沿用现有 rustls；不新增明文例外；域名白名单（微信的 request 合法域名）由宿主决定，引擎提供创建选项 `allowedDomains`（可选，空 = 不限制）。
7. **日志不打敏感数据**：`MINI_NET_LOG` 等只打 URL 与长度，不打 body；取证 JSON 里隐私字段替换成类型名（05 §2.2）。
8. **依赖**：新依赖一律精确版本（cpal、symphonia 的 vorbis feature、ANGLE 产物带 sha256）；ANGLE 的 BSD-3 许可证随包分发。

## 6. 不在范围内 / 已知差距

| 项 | 说明 |
|---|---|
| 关系链、米大师、帧同步、广告投放的**数据与结算** | 依赖微信后台；接口与环境照做（11 §6） |
| 帧同步服务 `getGameServerManager` | 依赖微信后台 |
| 相机、VK、AI 推理的**能力实现** | H 级，形状照做（10），能力交宿主 |
| 虚拟支付、广告的真实实现 | 只提供宿主代理接口，宿主接入 |
| H5 导出 | 编译器只对小程序；小游戏报「不支持导出 H5」 |
| Canvas 2D `filter` | CPU 不支持就忽略并打一次日志（G9 评估） |
| iOS Flutter 上的 WebGL | 纹理路线只有 CPU（`engine_gpu.rs:16-17`），需要新的 surface 种类，计划外 |
| 鸿蒙 | `SurfaceKind::supported_on_target` 目前不认鸿蒙，计划外 |
