# 04 实现计划

## 0. 通用约定（每一期都适用）

1. **纯搬迁与改行为分开提交**（steering 20）。纯搬迁提交必须附「改前 / 改后」md5 对照：sample 15 页、news 6 页 `rust.png`，gallery 65 张（`git status --porcelain doc/gallery` 为空，`35_gif_frame4.png` 按已知噪声），`damage-check` 5/5，`sdk-parity` 15/15、6/6，`interaction-check` 与基线全部一致，`tab-click-check` 12/12。
2. **基线**：G0.1 在改动前的 `main` 上生成，目录一律 `target/baseline_*` 前缀（`clean-target.sh` 白名单）：`baseline_main_sample`、`baseline_main_news`、`baseline_main_ia`、`baseline_main_fin2_*`。小游戏的帧基线 `target/baseline_game_<夹具>/`（G1 起）。
3. **每期收尾**：`bash tools/regress-async.sh G<n>-收尾` 后台跑全量（跑的时候不改 Rust），结果贴进该期验收记录；跑完 `bash tools/clean-target.sh`。
4. **动了帧调度 / 上屏 / 宿主视图的期（G0.6、G2、G3、G6、G8）** 必须量顿挫：小程序侧重跑 `android-jank.sh query-slow` 与 `query-fastslow`（Flutter 与 `MINI_APP=native` 各一次），数字不许比 `doc/滑动顿挫避坑清单.md` 回退；游戏侧跑 05 §5 的游戏场景。
5. **真机构建串行**：引擎库 → `flutter build apk` / `./gradlew assembleRelease` → 装包，一条一条跑（steering 30）。
6. **每个新 `.rs` ≤ 500 行**，例外写文件头理由；临时探针 `examples/tmp_*` 用完删源文件。
7. **测试放置**：游戏单测进 `src/tests/game_*_tests.rs`；游戏 e2e **只新增一个**集成测试文件 `tests/game_e2e.rs`（理由：每个 `tests/*.rs` 约 75MB 且单独链接；同一二进制内用 `static SERIAL: Mutex` 串行，因为包根目录是进程级）。
8. **文档同步**：每期把新增开关写进 `README.md` 与 `README.zh-CN.md`，判据与数字写进 `doc/引擎测试说明.md` 的新章节「五之四、小游戏」，顿挫数字写进 `doc/滑动顿挫避坑清单.md`。
9. **估算**为单人全职人日的粗估区间，含测试与文档，不含等待真机 / 取证的日历时间。
