# 08 测试代码与执行手册

05 规定了**测什么、判据是什么**，07 给了夹具源码；这一章给出**测试代码长什么样、命令怎么敲、输出长什么样、真机手测怎么一步一步做**。
文中的 Rust / 脚本是实现时的目标形态，接口名（`GameHarness` 等）在 G1 落地时以实际代码为准，这里先约定好。

## 1. e2e 测试骨架：`tests/game_e2e.rs`

只有这一个集成测试文件（04 §0.7）。文件头注释照写下面这段「为什么」：

```rust
//! 小游戏 e2e：驱动 GameEngine 跑 sample-game/ 下的夹具，断言帧序列、事件序列、像素统计。
//!
//! 为什么只有一个文件：每个 tests/*.rs 是独立二进制（约 75MB）外加一份增量缓存，还要单独链接一次
//! （steering 30）。为什么串行：包根目录（assets::APP_ROOT）与数据目录是进程级的，两个用例并行会互相读到
//! 对方的 wxfile / storage。为什么用无头帧时钟：rAF / 定时器 / performance.now 都跟它走，结果逐帧可复现。

mod game_harness;   // tests/game_harness/mod.rs（随这个文件一起，不单独成测试二进制）
use game_harness::*;
use std::sync::Mutex;

static SERIAL: Mutex<()> = Mutex::new(());
```

### 1.1 `GameHarness` 约定（`tests/game_harness/mod.rs`）

```rust
pub struct GameHarness {
    pub engine: mini_render::game::GameEngine,
    pub hz: u32,             // 无头刷新率，帧 n 的时刻 = n * 1000 / hz（毫秒，f64）
    pub frame: u64,          // 已 pump 的 vsync 数
    pub log: Vec<String>,    // 引擎侧 console 输出（逐行），夹具的 T:* 行从这里解析
    _dir: TempGame,          // Drop 时删除拷贝出来的夹具目录与 data_dir
}

impl GameHarness {
    /// 把 sample-game/<name> 连同 _lib 拷到 CARGO_TARGET_TMPDIR/<name>-<pid>/，建引擎（375×667@2，CPU 后端，
    /// MINI_FAKE_NOW 与 MINI_RANDOM_SEED 由 opts 注入，不读进程环境——避免开发者 shell 里残留的变量污染用例）
    pub fn open(name: &str, opts: Opts) -> Self;
    /// 跑 n 个 vsync：每个 vsync 先送这一刻该到的输入（脚本），再 pump_ex(t)，再收日志
    pub fn vsyncs(&mut self, n: u32) -> &mut Self;
    /// 一直跑到日志里出现 `pat` 或超过 max 个 vsync（超了 panic 并打印最后 30 行日志）
    pub fn until(&mut self, pat: &str, max: u32) -> &mut Self;
    /// 多指脚本：语法同 --multitouch（07 §5）；时刻相对当前帧
    pub fn touches(&mut self, script: &str) -> &mut Self;
    /// 解析出全部 `T:FRAME`、`T:EV <name>`
    pub fn frames(&self) -> Vec<(u64, serde_json::Value)>;
    pub fn events(&self, name: &str) -> Vec<serde_json::Value>;
    /// 断言：没有 T:FAIL、没有 [error]（除夹具声明允许的）、没有引擎 panic 日志
    pub fn assert_clean(&self);
    /// 主画布后备缓冲（RGBA8 非预乘）与输出缓冲（合成后）
    pub fn canvas_rgba(&self) -> (u32, u32, Vec<u8>);
    pub fn output_rgba(&self) -> (u32, u32, Vec<u8>);
    /// 像素工具：某颜色的包围盒、某颜色像素数
    pub fn bbox_of(&self, rgb: [u8; 3]) -> Option<(u32, u32, u32, u32)>;
    pub fn count_of(&self, rgb: [u8; 3]) -> usize;
}

pub struct Opts {
    pub hz: u32,                 // 无头刷新率
    pub query: &'static str,     // 启动 query（夹具参数）
    pub seed: u32,               // MINI_RANDOM_SEED
    pub fake_now: &'static str,  // MINI_FAKE_NOW，默认 "2024-03-15"
    pub backend: Backend,        // 逐字节判据一律 Cpu
    pub audio_offline: bool,     // 不开设备，按帧数推进音频时钟
    pub sync_decode: bool,       // 图片解码同步完成（第 k 帧 onload 必定已触发）
    pub watchdog_ms: u32,        // 看门狗，用例里调小，别真等 5 秒
    pub gpu_fault: Option<&'static str>, // MINI_GPU_FAULT
}
impl Default for Opts {
    fn default() -> Self {
        Self { hz: 60, query: "", seed: 1, fake_now: "2024-03-15", backend: Backend::Cpu, audio_offline: true,
               sync_decode: true, watchdog_ms: 5000, gpu_fault: None }
    }
}
// 这些都经 GameEngine 的创建选项注入，不 set_var：同一进程里 env 是全局的，串行用例之间会残留
```

> 像素断言**只用颜色统计和包围盒**，不读 PNG 文件：PNG 刚写出来工具要等约 1 分钟才读得到（steering 30），而且统计比看图准。

#[test]
fn k1_方块每帧右移一像素() {
    let _g = SERIAL.lock().unwrap();
    let mut h = GameHarness::open("g-square", Opts { query: "max=120", ..Default::default() });
    h.until("T:DONE", 200);
    let f = h.frames();
    assert_eq!(f.len(), 120, "rAF 次数");
    for (i, (_, v)) in f.iter().enumerate().skip(1) {
        let dt = v["dt"].as_f64().unwrap();
        assert!((dt - 16.667).abs() < 0.001, "第 {} 帧 dt={dt}", i + 1);
    }
    // 最后一帧：红块左边沿 = 120 × k（k = 画布宽 / 窗口宽，默认尺寸下 k = 1）
    let (x0, _, _, _) = h.bbox_of([255, 0, 0]).expect("没画出红块");
    assert_eq!(x0, 120);
    h.assert_clean();
}

#[test]
fn k3_144hz_下仍是60fps且2与3个周期交替() {
    let _g = SERIAL.lock().unwrap();
    let mut h = GameHarness::open("g-square", Opts { hz: 144, ..Default::default() });
    h.vsyncs(144 * 2);                                  // 2 秒
    let dts: Vec<f64> = h.frames().iter().skip(1).map(|(_, v)| v["dt"].as_f64().unwrap()).collect();
    assert!((119..=121).contains(&(dts.len() + 1)), "2 秒应当 120±1 次 rAF，实际 {}", dts.len() + 1);
    for d in &dts { assert!((d - 13.889).abs() < 0.01 || (d - 20.833).abs() < 0.01, "意外间隔 {d}"); }
    let mean = dts.iter().sum::<f64>() / dts.len() as f64;
    assert!((mean - 16.667).abs() < 0.2, "平均间隔 {mean}：节拍在累积误差（02 §4.2 的反例写法）");
}

#[test]
fn t2_双指交错按下抬起() {
    let _g = SERIAL.lock().unwrap();
    let mut h = GameHarness::open("g-touch-draw", Opts::default());
    h.until("T:READY", 10)
     .touches("7:100,200@0;9:300,400@16;u7:100,200@32;u9:300,400@48")
     .vsyncs(6);
    // 期望 touches 长度依次 1、2、1、0，changedTouches 每次 1
    let starts = h.events("touchstart"); let ends = h.events("touchend");
    assert_eq!(starts.iter().map(|v| v["ids"].as_array().unwrap().len()).collect::<Vec<_>>(), vec![1, 2]);
    assert_eq!(ends.iter().map(|v| v["ids"].as_array().unwrap().len()).collect::<Vec<_>>(), vec![1, 0]);
    // identifier 全程不变：第一根手指抬起事件的 changed id = 第一次 touchstart 的 id
    assert_eq!(ends[0]["ch"][0][0], starts[0]["ch"][0][0]);
    assert!(starts.iter().chain(ends.iter()).all(|v| v["ch"].as_array().unwrap().len() == 1));
    assert!(h.count_of([255, 0, 0]) > 0 && h.count_of([0, 255, 0]) > 0, "两根手指各画一个点");
}

## 3. 真机手测清单

自动化覆盖不到的（系统交互、听感、手感）用清单，每条记录「通过 / 失败 / 未测 + 现象」到 `game-doc/验收/G<n>.md`。
开测前统一检查：前台是示例 App、`lastUpdateTime` 是刚装的那次、引擎库 md5 = jniLibs 那份、`MINI_FPS` 行里的后端是本轮要测的后端（steering 30）。

### 3.3 生命周期与方向（G6）

| # | 步骤 | 期望 |
|---|---|---|
| M-L1 | `g-lifecycle`：回桌面 / 回来 ×3 | `hide`/`show` 各 3 次、成对；回来第一帧无黑闪（与小程序 `resume` 场景同一判据） |
| M-L2 | 锁屏再解锁 | 同上 |

## 5. FFI 契约测试（`src/tests/game_ffi_tests.rs`）

每个新函数（02 §13）一组：
- 空指针：`mr_app_touch(NULL, …)`、`mr_app_kind(NULL)` 等返回 0，不崩。
- 错误实例种类：对小程序实例调 `mr_app_next_wake_ms` 返回 -1、`mr_app_preferred_fps` 返回 0；对游戏实例调 `mr_app_navigate` 返回 0、`mr_app_back` 返回 0、`mr_app_page_depth` 返回 0，且 `mr_app_last_error` 含「小游戏实例不支持」。
- 非法参数：`phase=9`、`id=-1`、`x=NaN`、`force=-3` → 忽略该事件并写 `last_error`，后续正常事件照常。
- **panic 防护**（09 §2.1）：注入 `MINI_GAME_FAULT=panic@pump` → `mr_app_pump_ex` 返回 0、`last_error` 为 panic 信息、实例标记为已失效，之后所有调用返回 0；进程不 abort。
- 头文件：`scripts/gen-header.sh` 生成后 `git diff include/mini_render.h` 只包含新增函数（不改已有签名）。
- JNI：`nativeTouch` 等签名与 Kotlin 声明一致（`sdk/android` 的 `./gradlew assembleRelease` 编过即可证明链接；运行期 `UnsatisfiedLinkError` 由示例 App 启动验证）。

## 7. 失败分诊

| 现象 | 先看 | 常见原因 |
|---|---|---|
| `T:FRAME` 次数不对 | `MINI_RAF_LOG=1` 每帧一行 | 节拍器用了上一次实际时刻（02 §4.2 反例）；`--hz` 没传进帧时钟 |
| 无头两次运行 md5 不同 | 夹具里有没有 `Date`、`Math.random`、墙钟 | 没用 `T.rand()`；解码不是同步模式；`MINI_FAKE_NOW` 没生效 |
| GPU 与 CPU 有差异 | `gpu-parity.sh` 的差异包围盒 | 着色器用了硬件采样器；定点舍入两边不一致 |
| 触摸 identifier 变来变去 | `MINI_TOUCH_LOG` | 宿主按 `getPointerId(index)` 取错（用了 index）；iOS 映射表没在 ended 时释放 |
| 真机静音 | `MINI_AUDIO_LOG=1` | 构建没开 `game-audio` feature；iOS 会话类别；Android 焦点被拒 |
| 回前台卡一下 | `MINI_RAF_LOG` 看回来第一帧 | 补跑了 setInterval；解码缓存在 onHide 被清，回来全部重解 |
| 小程序回归变了 | `regress.sh` 汇总哪一步 | 共享件搬迁不是纯搬迁；prelude 分组改了顺序 |
| 截图是别的 App | `dumpsys window` 前台 | 共享手机被别的会话占用，重跑（steering 30） |
