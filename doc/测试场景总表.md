# 测试场景总表

每一轮测试都按这张表对照：每个功能由哪个测试守着、怎么跑、跑多久、怎么判、这一轮过没过。
没跑的项写原因，不留空格。判据细节与能力矩阵见 [引擎测试说明](引擎测试说明.md)，真机顿挫的坑与当前数字见
[滑动顿挫避坑清单](滑动顿挫避坑清单.md)，固定流程见 [`.kiro/steering/30-test-and-cleanup.md`](../.kiro/steering/30-test-and-cleanup.md)。

## 0. 每轮怎么跑

| 步 | 做什么 | 命令 | 用时 |
|---|---|---|---|
| ① 定向速测 | 只测改到的那块，先把发现的问题修掉 | `cargo test --release --lib <过滤词>`、`cargo test --release --test <文件>`、对应的真机脚本 | 2~30s |
| ② 全量（后台） | 第一节的 9 步 | `bash tools/regress-async.sh <标签>`，看 `target/test_batches/<批次>/summary.txt` | 13~14 分钟 |
| ③ 真机 / 模拟器 | 按第三节「什么改动必须跑」那一列挑 | 见第三节 | 每项十几秒到两分钟 |
| ④ 对照填表 | 在第五节加一轮：每项 ✅ / ❌（附数字）/ 没跑（附原因） | — | — |

测得快的几条（2026-11-01 实测）：

- **等待一律轮询**：等「🎮 第一帧上屏」、播放器状态、`[事件] page`，条件一到就往下走，不写死 sleep。
  `android-game-exit-audio.sh` 一个游戏从打开到判完 8~10s；按固定 12s 预热算，12 个游戏要多等两分钟多。
- **超时按墙上时钟算，不按次数**：一次 `dumpsys` / `logcat -d` 在一加 PLY110 上要几百毫秒，按次数写的「40 秒」实际等了 122 秒。
- **日志开一条 logcat 流写进本地文件再 grep**，别反复 `logcat -d` 从头翻：PLY110 的 logcat 环只有 256KB，ColorOS 几十秒就冲掉，
  要找的那一行可能已经没了。
- **全量放后台**：跑的时候写文档、跑真机，不改 Rust 源码（跑的就是工作区）。
- **定向用例很快**：lib 单测 1038 个全跑 2.9s；集成测试里最慢的是 `game_e2e`（119 个用例 208s），其次是示例小程序 e2e（每个文件 5~30s）。
- **真机构建串行**：引擎库 → `flutter build apk` / `./gradlew assembleRelease` → 装包。功能先在模拟器（emulator-5554）上验，手机留给计时、顿挫、GPU。
