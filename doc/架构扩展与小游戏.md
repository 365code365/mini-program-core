# 架构扩展：开闭原则审计与小游戏运行方案

2026-10-24。对照微信官方文档把组件、接口实现核了一遍，修掉一批确定的偏差（第 1 节），再看架构离「加一类应用（小游戏）、加一个标签、加一个接口只加代码不改旧代码」还差什么（第 2 节），最后给出小游戏的分期方案与判据（第 3、4 节）。

## 1. 这一轮修掉的偏差

每条都有用例守着，改回去就失败。

| 范围 | 从前 | 现在（微信语义） | 用例 |
|---|---|---|---|
| 异步 API 回调时机 | `showToast` / `showLoading` / `hideToast` / `setNavigationBar*` / `setClipboardData` / `vibrate*` / `pageScrollTo` 等在调用栈里**同步**回调 | 下一轮事件循环回调（`__uiDone` / `__syncOk`） | `wx_semantics_tests::异步_api_的回调在下一轮事件循环` |
| 下拉刷新 | `start/stopPullDownRefresh` 回调不带 `errMsg`、不返回 Promise | `{errMsg:'stopPullDownRefresh:ok'}`，无回调时返回 Promise | 同上 |
| setData 回调 | 同步调用，回调里量节点量到的是旧布局 | 画出来之后（下一轮事件循环）再回调，`this` 是实例 | `route_tests::test_setdata_callback_runs` |
| 定时器 | `setTimeout(cb, d, ...rest)` 丢掉 rest；同一时刻到点的按 HashMap 顺序触发（两个 `setTimeout(fn,0)` 可能倒着跑） | rest 交给回调；按到点时刻、同刻按登记先后 | `set_timeout_把多余参数交给回调`、`异步_api_的回调在下一轮事件循环` |
| storage | 字符串原样存、读时 `JSON.parse`：存 `'42'` 读回数字、存 `'true'` 读回布尔 | 一律 JSON 存，类型原样读回；旧版本存下的裸字符串照旧按原文读 | `storage_读回来类型不变` |
| `RequestTask.abort()` | 只调 `complete`；下载 / 上传任务 abort 后什么回调都没有 | `fail({errMsg:'request:fail abort'})` 再 `complete` | `request_abort_走_fail_再_complete` |
| 表单请求 | `content-type: x-www-form-urlencoded` 的对象 data 也发 JSON；GET 的字符串 data 被丢掉 | 按表单编码；字符串拼进 query | `request_表单编码与_get_字符串参数` |
| 布尔属性 | 不带值的属性解析成空串，组件按 `== "true"` 判：`<button disabled>`、`<switch checked>`、`<picker disabled>`、`<progress show-info>` 全是假 | 不带值是 `"true"`；绑定求出空串 / `false` / `0` 是假（`attr_is_true`，全部组件共用一个） | `不带值的属性是_true_绑定求空是假` |
| dataset 键名 | `data-row-index` 进事件是 `dataset['row-index']` | `dataset.rowIndex`；大写转小写（`data-Mixed` → `mixed`） | `input_semantics_e2e::dataset_键名转驼峰` |
| picker 事件对象 | 走 `__callPageMethod`：`e.type` 是 `tap`、`currentTarget.dataset` 被换成 detail、`fields="year"` 的 "2024" 变成数字、不冒泡 | 与 tap 同一条事件链：`type` 是 `change` / `cancel` / `columnchange`，`currentTarget` 是 picker 自己，会冒泡、可 catch（`picker_sheet::emit`） | `picker_e2e::change_event_object_matches_wechat` |
| `bindinput` 返回值 | 忽略 | 返回字符串就替换输入框内容（SDK 与桌面窗体同一条规则） | `input_semantics_e2e::bindinput_返回字符串替换内容` |
| image 默认尺寸 | 150×100，外加强制 4px 圆角 | 320×240、无圆角（H5 导出同步） | 回归 gallery / 快照 |
| image `widthFix` / `heightFix` | 没实现：高度永远是默认值 | 按原图比例（本地图读文件头、远程图到了整页重排） | 回归快照 |
| image 九种裁剪 mode | `top` / `center` / `bottom right` … 全按 scaleToFill 拉伸 | 不缩放、贴边、裁到框（H5 用 `object-fit:none` + `object-position`） | `image::crop::tests` |

### 还没对齐的（已确认，按影响排）

| 项 | 现状 | 为什么这轮没做 |
|---|---|---|
| dataset 值类型 | `data-code="007"` 被还原成数字 7（`__coerceDataset` 按长相猜） | 属性在模板展开时就变成了字符串，`{{12}}` 与 `"12"` 分不开；要让模板给整段表达式的属性留下 JSON 类型，改动面大，单独做 |
| 事件 `mark` | 原生事件对象里没有 `mark`，`mark:xxx` 属性不解析 | 要沿祖先链收集（含没有绑定的祖先），事件链现在只有带绑定的节点 |
| region picker | `detail` 只有 `value`，没有 `code` / `postcode`；数据是精简子集 | 缺一份完整行政区划表（带编码） |
| 输入框 | `cursor` 恒为末尾、`keyCode` 恒 0；`selection-start/end`、`auto-height`、`bindlinechange` 没有（`bindkeyboardheightchange` 已有：宿主推 `keyboardHeightChange` 时送到键盘所属的输入框，见 `host/engine_keyboard.rs`） | 要接宿主 IME 的真实光标与键码 |
| button | `loading`（转圈）、`open-type`（share / getPhoneNumber / chooseAvatar → 宿主）没有 | `open-type` 要先定宿主接口（与 `hostApis` 同一条路） |
| text | `space`、`decode` 没有；首尾空格被 trim | 与换行规则一起改，牵动 gallery 基线 |
| `SelectorQuery.in(component)` | 返回自身，组件里按 id 查会查到页面或别的实例 | 需要按组件实例划分节点作用域 |
| `showModal` | `editable` 输入框没有，结果里没有 `content` | 浮层里要接输入法 |
| 网络 | `onHeadersReceived` 不触发、`responseType:'arraybuffer'` 不认、`cookies` 恒空 | 原生网络层要把这些带回来 |
| storage | 没有单键 1MB / 总量 10MB 的上限检查 | 错误文案要先在真机上取证 |

## 2. 开闭原则：现状与要改的地方

结论：**「标签」与「wx 接口」两条扩展线已经有登记点，但没有闭合**；「应用种类」这条线完全没有扩展点，`MiniEngine` 是唯一的、按小程序页面模型写死的实现。按改动收益排：

1. **`MiniEngine` 是上帝结构**（`src/host/engine.rs`，约 90 个字段、45 个 `impl MiniEngine` 文件）。通用部分（JS 运行时、定时器、网络、存储、文件、音频、帧时钟、后端选择、surface、指针、生命周期、宿主事件）与小程序专用部分（页面栈、WXML 渲染器、tabBar、导航栏、胶囊、侧滑返回、picker 面板、Toast/Modal）混在一个结构里。加小游戏只能在 `pump_frame` 和每个输入入口里加分支。
2. **标签行为散在 `TagSpec` 之外**。`registry.rs` 的 `TAGS` 只管 build / draw / leaf / stateful / clips；布局修正（`layout.rs` 的 swiper / picker-view / grid-view / scroll-view）、绘制分派（`draw_interactive.rs`、`draw.rs`）、交互登记（`interactions.rs`、`builtin_hits.rs`、`host_regions.rs`、`hit_test.rs`）、状态镜像（`interactive.rs`、`form.rs`）、失效分析（`invalidate*.rs`）、H5 映射（`transpile/tags.rs`、`css.rs` 的 `WX_TAGS`）还有约 20 处按标签名的 match。`scroll-view` 出现在 16 个非测试文件里。
3. **标签清单重复**：`TAGS`、H5 的 `map_tag` 与 `WX_TAGS`、`native_placeholder.rs`、`builtin_components` 的 `BUILTINS`（再抄一份进 `app-info.js` 的 canIUse，靠测试守）。
4. **包种类写死**：`page_loader::load_app_json` 没有 app.json 时静默给一个默认配置；`app_dir::is_mini_app`、`launcher`、`compiler::load_app_source`、`bin/window.rs` 都按 app.json 认包。
5. **原生桥是封闭枚举**：`BridgeEvent`（`js/bridge.rs`）+ `runtime/app.rs` 的 match；`__native_*` 56 个，分在三个文件里命令式注册。`HostRequest{kind}` 已经是开放通道，但消费方仍要在 host 里按 kind 手写。
6. **prelude 只有一张表**（`js/api.rs` 的 `PRELUDE`）：小游戏不该装 `app-page` / `route` / `tabbar` / `component*`，现在没法按应用种类选。
7. **合成层固定成「页面 + fixed + tabBar + 浮层」**（`compositor/mod.rs` 的 `FrameLayers`）：没有「一整屏画布」这种层。
8. **两个宿主重复实现**：桌面窗体 `bin/app_window/*` 与 SDK 各写一份 tabBar / 胶囊 / 指针（这轮 picker 与 `bindinput` 都得两边各接一次）。

### 目标形状

```
            ┌──────────────── 宿主（SDK / 桌面 / 无头）：只认 Engine ────────────────┐
            │  mr_app_* / JNI / Swift：pump、surface、指针、生命周期、hostCall、事件   │
            └───────────────────────────────┬───────────────────────────────────────┘
                                            │
        Engine { kernel: Kernel, scene: Box<dyn Scene> }   ← FFI 不变，按 Scene 分派
                                            │
   ┌────────────────────────────┬───────────┴───────────────┬──────────────────────────┐
 Kernel（通用，所有应用种类共用）  Scene: MiniProgram（现有）     Scene: MiniGame（新增）
 JsRuntime + 原生模块注册表        页面栈 / WXML / tabBar / 导航栏   game.js / 主画布 / rAF / 全局触摸
 定时器 / 网络 / 存储 / 文件 / 音频  WxmlRenderer + TagSpec 注册表   Canvas2D（已有）/ WebGL（后期）
 帧时钟 / 后端选择 / 合成器 / surface  prelude: 小程序那一套            prelude: 内核 + game 那一套
```

- **`AppProfile` 注册表**：`detect(dir) -> bool`（有 game.json 就是小游戏，有 app.json 就是小程序）、`preludes() -> &[Prelude]`、`create(kernel, opts) -> Box<dyn Scene>`。新应用种类只加一个 profile，不改 Engine。
- **`Scene` trait**：`pump(&mut self, kernel, now) -> FrameFlags`、`pointer(&mut self, ev)`、`frame_layers()`、`on_show/on_hide`、`as_router() -> Option<&mut dyn Router>`（`launch / navigate / back / page_depth` 这些只对小程序有意义，小游戏返回 None，FFI 回「不支持」而不是崩）。
- **原生模块注册表**：每个模块自带 `register(rt)` 与 `pump(&mut Kernel)`（取自己的回包、回调 JS），`BridgeEvent` 不再加变体；`HostRequest` 按 kind 找处理器（`HashMap<&str, Box<dyn HostRequestHandler>>`）。
- **TagSpec 补钩子**：`layout_fixup`、`interaction`（登记命中区 / 交互状态）、`invalidation`（这个标签变了影响多大）、`h5`（H5 端标签与默认样式）。一个标签一行 + 一个模块，散落的 match 逐个迁过去。H5 的 `map_tag`、`WX_TAGS`、canIUse 列表从注册表生成。

### 迁移顺序（每一步都是纯搬迁，单独一次改动，逐字节证明等价）

1. prelude 按 profile 分组（`core` / `mini-program` / `mini-game`），小程序装的集合与顺序不变 —— 判据：`prelude_names()` 与改前相同，gallery 65 张、21 页快照 md5 不变。
2. 包种类探测 `AppProfile::detect`，`app_dir` / launcher / page_loader 改用它 —— 判据：同上，外加没有 app.json 的目录不再静默套默认配置而是报「不是小程序也不是小游戏」。
3. 从 `MiniEngine` 拆出 `Kernel`（字段搬家，方法签名不变）—— 判据：damage-check、sdk-parity、interaction-check、真机 `android-jank.sh query-slow / query-fastslow` 不回退（这一步动帧调度，必须量顿挫）。
4. `Scene` trait + `MiniProgramScene`（现有逻辑原样包进去）—— 判据同 3。
5. TagSpec 补钩子，按 scroll-view → swiper → input → button → picker 的顺序把 match 迁进表 —— 判据：每迁一个标签跑一次 gallery + 快照 md5。
6. 原生模块注册表，`BridgeEvent` 冻结 —— 判据：`cargo test` 全绿，`__native_*` 名单与改前相同。

## 3. 小游戏：要什么、已有什么

| 能力 | 小游戏需要 | 引擎现状 |
|---|---|---|
| 包结构 | `game.json`（`deviceOrientation`、`subpackages`…）+ `game.js` | 只认 app.json，没有 app.json 时套默认配置、`game.js` 不会执行 |
| 全局对象 | `GameGlobal`、`require`、`wx` | `require` / CommonJS 已有（`module.js` + `register_all_modules`） |
| 主画布 | 第一次 `wx.createCanvas()` 是上屏画布，之后的是离屏 | 2D 光栅化与指令解释器已有（`renderer/components/canvas`，`createOffscreenCanvas` 走的就是它），但上屏必须经 WXML 页面 |
| 帧循环 | `requestAnimationFrame` 跟 vsync，回调参数是时间戳 | 只有 `setTimeout(cb,16)` 的垫片，不跟 vsync |
| 触摸 | `wx.onTouchStart/Move/End/Cancel`，全局、不经命中 | 只有 WXML 命中后的元素事件 |
| 音频 / 网络 / 存储 / 文件 | 与小程序同一套 API | 已有，可原样复用 |
| 分包 | `wx.loadSubpackage` | 只有 `preDownloadSubpackage` 桩 |
| WebGL | 大多数商用小游戏引擎（Cocos、Laya、Three）走 WebGL | 没有；GPU 后端只做合成 |
| 开放数据域 | `wx.getOpenDataContext` | 没有（依赖微信关系链，宿主侧也拿不到，明确不支持） |

## 4. 小游戏分期与判据

前提：第 2 节迁移的 1~4 步完成（profile 探测、Kernel / Scene 拆分），小游戏是新加的 `MiniGameScene`，小程序代码不动。

| 期 | 内容 | 判据（可判定） |
|---|---|---|
| G1 | `game.json` 探测、`GameGlobal`、只装内核 prelude + game prelude、执行 `game.js`；`launch/navigate/back` 对小游戏回「不支持」 | 示例小游戏 `console.log` 出现在宿主日志；小程序 65 张 gallery 与快照 md5 不变 |
| G2 | `wx.createCanvas()` 主画布作为一整屏合成层（`FrameLayers` 加单层形态）；`requestAnimationFrame` 回调队列在 `pump` 里按宿主 vsync 时间戳冲刷；`FRAME_WANTS_MORE` 由「有没有挂着的 rAF」决定 | 画一个每帧移动 1px 的方块：无头 `--frames 60` 逐帧位移恰好 1px；一加 PLY110 上 `android-jank.sh` 屏上重复 ≤1%、引擎 >8ms 帧 0（CPU / GPU 后端分别给数） |
| G3 | `wx.onTouchStart/Move/End/Cancel` / `offTouch*`，事件形状 `{touches, changedTouches, timeStamp}`（`identifier`、`clientX/Y`），多指 | 无头 `--touch` / `--drag` 脚本断言回调序列与坐标；SDK 与桌面同一份（`host::input`） |
| G4 | `wx.loadSubpackage`（本地分包目录）、`getSystemInfoSync` 的游戏字段、`onShow/onHide`、横竖屏（`deviceOrientation`） | 分包里的模块 `require` 得到；横屏游戏在竖持设备上画面与触点一起转 90° |
| G5 | WebGL：GPU 后端上给一个 WebGL 1 子集（wgpu 实现）；CPU 后端**不支持**并明确 fail（`getContext('webgl')` 返回 null，日志写明） | Three.js 官方 `webgl_geometry_cube` 跑起来，与 Chrome 截图差异 ≤ 定死的阈值；CPU 后端不崩、不黑屏 |
| 不做 | 开放数据域、虚拟支付、广告组件 | 返回微信同名错误，`canIUse` 报 false |

验证素材：在 `sample/` 外另放 `sample-game/`（2D 方块、触摸画线、音频、分包各一个最小游戏），不进小程序的像素基线。
