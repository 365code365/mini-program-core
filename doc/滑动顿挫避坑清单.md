# 滑动顿挫避坑清单

「顿挫」= **屏上重复了一帧**：相邻两次上屏隔了一个以上的显示器周期。平均帧率、引擎自己的帧耗时都可能全达标而屏上照样顿，
所以判据只认两样：

1. **屏上**：SurfaceFlinger `--latency` 量引擎那一层每次上屏的时刻（不靠 App 内日志）；
2. **引擎**：`debug.mini.damage_log` 里每一帧重画了多少、花了多久（`整帧·…` 行末尾带 `← 源码文件:行号`）。

两样一条命令都给（宿主承载的原生组件——地图、视频——跟不跟页面是第三样，见下面「原生组件」那一节）：

```bash
bash tools/android-jank.sh query-slow                # Flutter 示例（sdk/flutter/example）
MINI_APP=native bash tools/android-jank.sh query-slow # 原生示例（sdk/android/example，MiniProgramView）
```

每一条坑的来龙去脉在 [踩坑记录](踩坑记录.md)，这里只列「改之前先对一遍」的清单与当前数字。

## 当前数字（一加 PLY110，90Hz，屏上重复占比）

| 场景 | Flutter 示例 | 原生示例·旧（Bitmap + onDraw，CPU） | 原生示例·SurfaceView（auto→GPU） | **预约 vsync 之后**（Flutter / 原生） |
|---|---|---|---|---|
| `query-slow`（「节点与滚动」慢拖，回调里 setData） | 2.0%（当天复测 3.7%） | 19.9% | 2.5% ~ 3.3% | **0.4~0.5% / 0.4~0.6%** |
| `query-fastslow`（快甩 + 慢拖） | 2.3% | 23.6% | 2.9% | 1.5% / 1.5% |
| `index-slow`（首页慢拖） | — | 7.1% | 0.4% | 0.4% / 0.4~0.9% |
| `enter-query`（进页面 + 返回 ×2） | 0 次，转场 29 帧 | — | 0 次，转场 29 帧 | 未复测 |
| `host-slow`（宿主页慢拖，经过同层渲染的 `<map>`） | 0.5% | — | 0.5% | 0.3% / 0.4% |
| `perf-slow`（综合场景：CSS 动画 + 每秒 setData + 同层视频） | 2.5% | — | 1.4% | 1.9% / 1.0% |

原生示例「旧 → 现在」是同一个引擎库、同一套坐标、都是 release 包，只换了 `MiniProgramView` 的上屏方式（2026-10-23）。
最后一列（2026-10-23 夜）同一个引擎库，只改宿主：tick 开头预约下一个 vsync（第 16 条），原生示例另把一个 MotionEvent 的采样打成一包 post。

`sheet`（点 ActionSheet → 点遮罩收起，原生示例）：GPU 2.0%（面板还画错，见踩坑记录）→ 0~2.5%（6 轮，剩下的重复都在
收起时 `fail` 回调的 setData 那一帧，pump 16~24ms）；`debug.mini.backend cpu` 稳态一帧 2.5~3.5ms，但动画开头大核还没升频，
屏上重复 4~30%。
改了上屏、帧调度、失效分析之后，至少重跑 `query-slow` 与 `query-fastslow` 两条，数字不许回退。

2026-10-27 复测（`feat/mini-game`，改了 canvas 的 fillRect / fill_path 快路，原生示例）：`query-slow` 0.4%，`query-fastslow` 2.3%。
`query-fastslow` 比表里的 1.5% 高，同一天把库换回 main `a950b9a` 是 2.2%：设备当天的状态，不是回退。**比较要同一天、同一台手机背靠背量。**

商店里的 news-app（`STORE_APP=news-app MINI_APP=native bash tools/android-jank.sh news-fastslow`，2026-10-24）：
**2.6%、最长空档 77ms → 0.9~1.5%、最长 44ms**。77 / 66ms 的空档都是甩到底时 `onReachBottom` 追加列表：
整页重排 + 整条带重画，pump 57~77ms（布局 10~14、换行 7~8、画 20~33）。改成切频道时一次给全、滚动中不再
setData（引擎没改）。剩下的 44ms 出现在「停住之后再次按下拖动」的第一帧（`✋ 重采样` 之后两个 vsync 才出新位置，
那两帧都是只合成 2ms），是起手判定 / 重采样的延迟，不是绘制慢 —— 待查。小程序里滚动中触底追加、带转圈动画的
「加载中」行，都是同一类坑。

**转一下屏，之后一直是 CPU（2026-10-24，Flutter 示例上传的诊断日志 20261024-143852）**：GPU 设备建的时候只要了
「当时画面尺寸」那么大的纹理上限（竖屏 1079×2312 → 2312）。手机转到横屏（2353×1037）时 `Surface::configure`
校验失败，整个会话回退 CPU，转回竖屏也不回来：之后每帧都是 CPU 光栅化 + 整张 `writePixels`（日志里 1212 行 skia），
上下滑一顿一顿。改成建设备时直接要适配器的上限（`compositor/gpu/device.rs`）；真机复测横屏 → 竖屏后仍是 GPU、
`writePixels` 0 次。**看诊断日志先看「[后端]」那一行**：auto 落到 CPU 的原因写在括号里。

停住再拖的第一下：重采样在拖动起步时多回取一帧（取样时刻落在第一个采样之前，页面原地不动），已改成起步时
正好落在第一个采样上、120ms 内退回正常回取量（`engine_resample.rs`）。但关掉重采样（`debug.mini.no_resample 1`）
同一场景也是 33~44ms，剩下的是方向锁定阈值（4px）加上 `adb input swipe` 从静止起步的事件节奏，不是绘制。

## 宿主侧（上屏与帧调度）

| # | 别这么做 | 为什么 | 应该 |
|---|---|---|---|
| 1 | 像素拷进 ByteArray → `Bitmap.copyPixelsFromBuffer` → `postInvalidate` → `onDraw` 里 `drawBitmap` | 每帧三次整帧拷贝（约 10MB）+ HWUI 再上传一次纹理；晚一个 vsync；UI 线程一忙就丢；只能走 CPU。原生示例实测 19.9% | 画到自己的 **SurfaceView**，引擎线程直接交帧（`EngineSession.kt` / Flutter `EngineHost.kt`） |
| 2 | Flutter 外部纹理（SurfaceProducer） | 屏上那一帧取决于 Flutter 自己这一帧有没有按时出，主线程一忙就重复 | 独立图层（`androidSurfaceView: true`，默认） |
| 3 | 后端固定 CPU | 滚动每帧都要 CPU 整帧合成 + 整帧写进缓冲区；GPU 下是「只合成」约 2ms | 偏好 `auto`，失败逐级回退（GPU → CPU 直写 Surface → Bitmap），回退有日志 |
| 4 | 不给 Surface 投帧率票 | ColorOS 没人要高刷就把整个屏降到 60Hz | `Surface.setFrameRate(最高刷新率)`（`surfaceChanged` 里） |
| 5 | SurfaceView 只实现 `Callback`、一建出来就显示 | 回前台时窗口不等它，露黑底一闪；第一次打开时黑块 | `Callback2.surfaceRedrawNeededAsync` 等引擎首帧（250ms 兜底，第一次打开不等）；首帧前 `alpha = 0` |
| 6 | SurfaceView `MATCH_PARENT` | 视图 1080、引擎 1079 像素时整帧被横向拉伸 1 像素，全屏发虚 | 缓冲区与布局都按引擎像素尺寸（`setFixedSize` + 同尺寸 LayoutParams） |
| 7 | 只在「这一帧有新画面」时续帧 | `setTimeout` / 网络回包在静止页面上停住 | 认 `FRAME_WANTS_MORE`，否则停下等输入 |
| 8 | `pump(此刻)` | 画的时刻相对 vsync 忽早忽晚，动画抖 | 传 Choreographer 的 `frameTimeNanos` |
| 9 | 移动事件不带时间、抽稀 | 一帧到几个事件是碰运气，慢拖一顿一顿；松手速度暴涨 | `nativePointerMoveAt(x, y, eventTime)`，历史点逐个送 |
| 10 | 在 UI 线程上建 / 驱动引擎；不管线程跑在哪个核 | 小核上补条带 5~11ms | 专用引擎线程（引擎自己绑大核）+ ADPF（`FrameBoost.kt`） |
| 11 | 导航栏关着（原生视图从前的默认） | 不是顿，但整页顶进状态栏、没有返回箭头、转场「一换就到」 | `navigationBar` / `routeAnimation` 默认开（与 Flutter 插件一致） |
| 12 | 把原生控件（地图、视频）**盖**在引擎画面上 | 两条上屏路：引擎画面系统合成器直接取，控件要等事件 → 主线程 → 宿主下一帧，晚 2~4 个 vsync 且每帧不一样；按 vsync 推算只推得准惯性。还会吃掉从它上面开始的拖动（页面拖不动） | **同层渲染**：宿主解码 / 画好帧交给引擎画进页面（视频 `sameLayerVideo`，地图这类 `sameLayerViews`），见下一节 |
| 13 | 同层组件每个滚动帧都重画、重交 | 白白占主线程与上传带宽；滚动时画面本来就在引擎画布里跟着走 | 只在内容变了时交帧（`invalidate` / Flutter 离屏树要重画时），引擎只重画那一块 |
| 14 | iOS：主线程 `CADisplayLink` 里 pump + `CGImage` 交给 `CALayer.contents` | 一帧几毫秒压在主线程上；子图层改 contents 默认带 0.25s 隐式动画（每帧都在淡入淡出）；只能 CPU | 引擎线程 + `CADisplayLink`，画面画进自己的 `CAMetalLayer`（GPU），CPU 退路关掉隐式动画（`actions` 全给 `NSNull`） |
| 15 | iOS：触摸不带时间、不要高刷 | 慢拖一顿一顿（同第 9 条）；ProMotion 机型默认被限在 60Hz | `mr_app_pointer_move_at(…, UITouch.timestamp × 1000)`；`preferredFrameRateRange` 要 120 + Info.plist `CADisableMinimumFrameDurationOnPhone = YES` |
| 16 | tick **最后**才 `postFrameCallback` 挂下一帧 | 这一帧一超过一个周期（setData + 覆盖层 11~13ms），下一个 vsync 已经过去，Choreographer 只能排到再下一个。一加 `query-slow` 屏上 21 次重复里 20 次就是它（`🎞` 日志：tick 间隔 22ms，前一帧 vsync→交出 11~13ms）。而 BufferQueue 本来有余量（入队到上屏约 25ms），晚 1~2ms 交上去赶得上 | 上一帧回报 `WANTS_MORE` 就在 tick **开头**预约，这一帧回报没活了再撤掉（静止页面照旧零耗电）。两份 Android 宿主都改了；iOS 的 CADisplayLink 一直挂着，不受这一条影响。`🎞` 第三列是 tick 开始时刻，分得清「pump 慢」还是「线程上前面压着别的活」 |
| 17 | 分栏（frameset）时挪图层与换图分在两次 Core Animation 提交里（macOS，2026-10-26） | 点会话打开聊天时两栏对调着显示一帧（左栏是聊天页、右栏是会话列表）。`applyFrameset` 自己 `CATransaction.begin/commit` 在最外层立刻提交了挪层，换图跟着 RunLoop 末尾的隐式事务晚一帧。另有：GPU 直画 Metal 层时宿主挪层晚一拍；hover-class 点击态冻进左栏留图 | 事件、另一栏的图、主画面包在**同一个显式事务**里（`EngineSession.swift`）；分栏期间整段走 CPU 合成（`frameset_holds_gpu`）；留图前撤点击态。**判据用真录屏**：`python3 tools/mac-split-flicker.py`（ffmpeg 60fps 录窗口 + cliclick 真点击，数 A→B→A 回跳）。轻聊连点会话：改前左栏 3 下 2 次回跳，改后 6 下 × 2 轮 0 次。`MINI_SPLIT_TRACE` 只记交出去的图，量不到这一类 |

## 原生组件（地图 / 视频）：别盖在画面上

「顿」也可能是**两层之间错开**：引擎那一层每帧都按时上屏了（SurfaceFlinger 量不出问题），盖在上面的控件晚了几帧。
量法是截屏量「地图上沿 − 卡片标题上沿」的变化（`python3 tools/android-native-align.py flutter <apk…>` / `native`）：

| 一加 PLY110，宿主页慢拖 700px / 2.5s，3 轮 × 8 张 | \|d\| 均值 | 最大 | ≤2px |
|---|---|---|---|
| Flutter 示例·地图盖在画面上（`--dart-define=SAME_LAYER_MAP=false`，带逐帧推算） | 2.8px | 15px | 15/24 |
| Flutter 示例·同层渲染（`sameLayerViews: ['map']`，离屏画成帧） | **0** | 0 | 24/24 |
| 原生示例·同层渲染（`sameLayerViews["map"]`，`MiniSameLayerView`） | **0** | 0 | 24/24 |

画进页面以后它就是页面画布里的一块像素，错位按构造就是 0，滚动时宿主一帧都不用重画；拖动从地图上开始照样滚页面
（与微信同层渲染的视频一致；地图自己的平移 / 缩放手势没有转，只转点击）。真地图 SDK 要能把那一帧画出来
（截图 / TextureView 接口），平台视图（google_maps_flutter）离屏画不出来就只能照旧盖着、接受错位。

## 引擎侧（谁逼出了整帧）

- 点击态（`hover-class` / `:active`）、事件回调里的 setData、内容变高、fixed 元素 `wx:if` 出现：都曾逼出 `整帧·结构`，
  现在各自只重画自己的盒子。新加的失效路径先看 `damage_log` 里有没有 `整帧`。
- setData 重建在真机上比桌面慢十倍的部分是**分配**（jemalloc 带锁）：热循环里的临时 Vec、级联深拷贝、克隆祖先链。
  热点要在真机上抓（simpleperf），桌面看不出来。
- `vec![Color::TRANSPARENT; n]` 不走 calloc，45MB 画布逐个写要十几毫秒。
- 动画（操作菜单 / picker / `@keyframes`）按宿主给的 vsync 时间取样；页面转场按帧推进（`StepClock`），不按墙上时钟。
- GPU 模式下的弹层只传它画过的那几行（`compositor::Footprint`），不要整帧直通。
- 「按编号判断纹理要不要重传」的缓存，编号要进程里唯一：GPU 自检跑在预热线程上，线程局部的编号会撞号（操作菜单白板没字）。
- **每画一个节点都走的函数里别分配**：`animated_image_frame` / `ident`（判「这块是不是动图 / 同层组件」）对每个 view、
  text 都调一次，先判标签再拼键（`host_view::key` 会分配字符串）—— 1000 个节点就是每帧 1000 次 jemalloc。
- **大块斜向渐变每次补条带都现算**：首页 135° 头图滑回顶部时补一条 1078×286 要 13~16ms（真机 simpleperf：引擎线程自身时间
  第一就是 `draw_linear_gradient` 的闭包）。现在面积 ≥12 万像素的斜向渐变按行缓存（键是元素在画布上的精确位置），
  算过的行原样贴回，逐字节相同。`index-long`（连续甩 + 慢拖 40 秒）引擎 >8ms 的帧 14 → **0**，屏上重复 1.8% → 1.7%，前后半段不变差。
- **本地大图同步解码**：选图的原图 5MB / 1200 万像素，同步解码一张 300ms+，解码后 48MB，三张就挤爆图片缓存、每帧逐出重解 ——
  选完图整页卡死。超过 768KB 的本地图后台解码、长边缩到 2048（`image/load.rs`、`image_net::get_or_load`），本帧先画占位。
- **聚焦输入框的光标闪烁**从前每翻一次 `mark_full`（键盘弹着时每 500ms 整条带 + 覆盖层 + tabBar），现在只重画输入框的盒子
  （`engine_press.rs` `damage_caret`，`tests/sdk_damage_caret.rs` 逐字节对照）；**网络回包**不再 `mark_full`，回调里的 setData
  走失效分析（网络图片到达仍整帧：固有尺寸可能改布局）。
- 每帧都走的 `scroll_view::tick` 不再克隆全部 `ScrollViewInfo`、不再 `entry(id.clone())`；定时器没到点不建 Vec；
  scroll-view 绘制路径上的 `MINI_SCROLL_LOG` 只读一次环境。
- 一加 `query-slow` 的剩余成本（simpleperf，引擎线程 12s）：GPU 上屏（vkQueuePresent + submit + acquire）占 pump 的一半多，
  每帧约 1ms 驱动开销；真正超预算的是回调 setData 那一帧：重建布局 3.5~4.9ms（建树占一半）+ 覆盖层重画，合计 11~13ms。
  预约 vsync 之后它不再丢帧，但仍是下一个要压的（setData 增量布局）。
- **setData 整棵重建里重复算的部分记下来**：样式落地（选择器匹配 + 声明落地）按「样式表编号 + 元素上下文的完整字节键」
  记忆（`style_apply/memo.rs`，`MINI_NO_STYLE_MEMO=1` 关掉对照），整段字宽按（文字、字号、字间距、粗细）记忆
  （`text/wrap_memo.rs`）。一加 `query-slow` 同样 12 秒：建树采样 313 → 176（-44%），整个重建 600 → 465（-22%）；
  全量回归逐字节不变。
- **setData 增量布局**（`wxml_renderer/layout_incremental.rs`）：没变的子树连同 taffy 节点与布局缓存原样留着，只重建变了的，
  taffy 只重排脏路径；失效分析读改之前拍下的旧布局（`layout_snapshot.rs`），布局之后改过的样式（换行补高、覆盖层重排）先还原。
  `MINI_LAYOUT_VERIFY=1` 每次增量之后整棵重建一遍逐节点比（全部测试跑过一遍 0 处不一致），`MINI_NO_INCREMENTAL_LAYOUT=1` 关掉。
  一加 `query-slow`：重建 3.5~4.9ms → **0.9~1.3ms**（建树 0.2、布局 0.1，剩下最多的是模板展开 0.4~0.7），
  回调 setData 那几帧整个 pump 11~13 → 9.0~9.4ms；屏上重复 0.4%。
  从前会退回整棵重建的几种情况已经去掉：子节点个数变了（列表增删）按前后缀同标签对齐，挪了位置的节点只要没有
  位置相关的选择器（`:first-child` / `:nth-*` 等）能命中就复用；纯标签改成黑名单（只有 `video` / `grid-view` /
  `live-*` / `camera` / `voip-room` 布局后还改样式）；旧树里的占位节点按「挪走的真节点」表解析，失效分析看到的旧树与整棵重建一样；
  只有滚动位置变了也走增量（帧计划仍是整帧）。剩下的限制：带 transform / 动画的子树变了就整段重建、不往里钻（transform 的失效要遍历旧子树），
  内容变矮仍出整帧。`tests/incremental_layout_e2e.rs`：106 次增量 vs 2 次整棵。
- 整屏压暗别逐分量查表（向量化不了）：`Footprint::apply_lut` 能写成乘法就按乘法算；弹层动画期间底图不动，留一份
  （`compositor::sheet_base`），别每帧重拼。

- **图片预览别在引擎线程上缩图、别在它底下重画页面**：从前每帧对原图逐像素浮点缩放 + 整屏临时缓冲混色，打开 / 预取那一帧
  盒式滤波一张 2048 的照片 30~45ms；盖着整屏时底下「媒体」页的动图还每 120ms 局部重画 + 传页面镜像（一帧 14~16ms）。
  现在缩图在后台线程（缩好前拿原图最近邻凑合），1:1 不透明的帧整行拷贝，黑底不透明时页面的重画留到它露出来（`engine_preview.rs`）。
  `android-jank.sh preview-swipe`：动作中掉帧 45% → **1.7%**（剩下的是点缩略图到第一帧的 60~90ms 触摸 → JS 延迟），只合成帧 p50 6.8ms。
  注意这页的「屏上重复」会把动图换帧之间 110~121ms 的静止空档也算进去，看动作中的掉帧要排掉 ≥100ms 的空档。
- **定高 scroll-view 当页面滚（页面本身不滚）**（兴趣圈帖子页，诊断 20261025-100253-98de9a）：嵌在 `<view>` 里、占屏 93% 的
  scroll-view，从前每帧把可见子节点整个重新光栅化（三张 135° 渐变图在视口里时一帧画 12ms），还有三处各自逼出整帧 ——
  一块大矩形被换成整条带（`engine_damage.rs`，连底下输入条一起画）、锁定 scroll-view 与到边界交给页面那一步（`input.rs`）、
  松手（`engine_input.rs`）。现在：① 那三处不再整帧；② 子树是静态内容的纵向 scroll-view 走**分块缓存**
  （`wxml_renderer/scroll_tiles.rs`）：内容按 512 行一块、块号定位置，只留视口上下各一块，滚动只把块整段拷回页面画布；
  按住里面的元素（按压态）、子树里有动画 / 表单组件 / 视频 / swiper 等时照旧逐帧画；`MINI_NO_SCROLL_TILES=1` 关掉对照；
  ③ 斜向渐变的行缓存第一次见的键不进缓存（`gradient.rs` `admit`，键带画布位置，scroll-view 里每帧都变、从来命不中）。
  一加 PLY110 原生示例 `STORE_APP=forum STORE_PATH=pages/post/post MINI_APP=native tools/android-jank.sh`，
  同一个包只拨 `debug.mini.no_scroll_tiles` 对照（两轮）：`store-slow` 屏上重复 **26.2% / 25.8% → 0.7% / 0.7%**、
  引擎 >8ms 的帧 271 → 51~64；`store-fastslow` **18.5% / 16.6% → 2.6~2.9%**（剩下的多是快甩到底停住的那 100ms 空档）。
  Flutter 示例 simpleperf（同一串拖动）：帧耗时 p50 14.8 → 7.6ms、超 11.1ms 的帧 449/705 → 23/881，画 p50 10.9 → 3.3ms。
  剩下最大的两块都是整段拷贝：块贴回页面画布（约 11MB 一帧）与 GPU 镜像上传同样那 11MB（`PageMirror::upload`），
  各占引擎线程两三成；再往下压要让 GPU 自己挪那块（镜像里按偏移拷贝，只传新露出的行）。
  测试：`tests/forum_post_scroll_jank.rs`（拖动全程不整帧、按压态与点击照旧、开 / 关局部重画逐字节一致）。
- **带 bindscroll 的列表别逼整帧、覆盖层里的列表别连页面一起画**（外卖店铺页 / 点餐页 / 「已选菜品」抽屉，2026-10-25）：
  ① scroll-view 派过事件（bindscroll 每帧都派）从前就 `mark_full`（`scroll_view.rs`），回调里的 setData 本来就走失效分析；
  ② 左侧分类的选中条 `wx:if` 一换（孩子 2 -> 1）从前整帧，现在按新旧两串孩子画到哪取范围（`invalidate_pair.rs`）；
  ③ 滚过的 scroll-view 里 setData，失效范围按没扣滚动偏移的布局坐标收 —— 会擦错地方、看得见的那行留旧字
  （`tests/sdk_damage_nested_scroll.rs` 抓到的老问题），现在里面变了就重画它整个盒子；
  ④ 分块缓存不再被每次 setData 整个丢掉：数据变了按子树签名（节点身份 + 文字 + 属性 + 布局）核对，没变接着用；
  ⑤ 覆盖层里的 scroll-view 动了只重画覆盖层里它那块（`engine_fixed_partial.rs`），页面一个像素不动，GPU 只补传那几行。
  一加 PLY110 原生示例：店铺页 `store-slow` 屏上重复 **25.7% → 1.8%**、`store-fastslow` 2.9%；点餐页 2.1% → **1.6%**，
  分类换高亮那一帧 28 → 14ms；抽屉列表拖动 264/264 帧超 11.1ms（每帧整条带 + 覆盖层 + 24MB 上传，p50 18.7ms）
  → **15/467、p50 7.6ms**（`store-slow` 打开抽屉 1.9%）。
- **支付密码键盘（覆盖层里的一排键）按一下别整层重画**：覆盖层里点击态 / 光标变了只清、只画那一块，GPU 只补传那几行
  （`LayerCanvas::write_rows`）；圆角不一样的大块背景（`border-radius: 24rpx 24rpx 0 0` 的面板）整格盖住的像素整段填
  （`paths.rs`，原来 4 条子扫描线逐像素算）；半透明遮罩盖在全透明上直接写源色（`shapes.rs`）。桌面 `tests/bank_pad_latency.rs`：
  按键那一帧 21.6 → 8.0ms，点击态帧覆盖层 17 → 0.3ms；一加上点击态帧 6.5ms（传 1MB，从前整层 12MB）。
  圆点变了的那一帧覆盖层仍整层重画（覆盖层的布局在画的时候按视口重排，失效分析的布局坐标对不上它）：一加上 9~21ms，
  后面几轮测量时手机前台被别的 App（游戏）占着，数字不作数。
- **键盘顶起画面交给引擎**（`engine_keyboard.rs`）：从前 Android SDK 给 SurfaceView 做 `translationY` 动画 —— 引擎画的导航栏
  被推出屏幕、内容顶到状态栏底下，SurfaceView 位置与引擎出帧不同步，顶起那 200ms 一顿一顿。现在宿主只报目标上移量
  （`nativeSetKeyboardShift` / `mr_app_set_keyboard_shift`），引擎按帧缓动、合成时导航栏以下整体上移
  （`FrameLayers::content_shift`，CPU `render_shift.rs` 与 `compose.wgsl` 同一套，GPU 对拍带上移的配置逐字节相同），
  触摸坐标引擎自己换回去。聚焦 / 失焦只重画新旧两个输入框（从前整页）。一加上点「附言」：聚焦那一帧 31ms 整帧 → 9.4ms 局部，
  顶起过程每帧只合成 1.2~1.8ms，导航栏原处不动（`tests/keyboard_shift_e2e.rs`）。Flutter 插件 Android 也改走引擎
  （`view.dart` 把顶起量经 `keyboardShift` 交给引擎，视图不再 Transform；真机顶起前后导航栏那几行逐像素相同）；
  iOS 两个宿主还是平移视图，没接。盖在画面上的原生控件按顶起量跟着报位置（`engine_events.rs`）。
- **包里的图在绘制时同步解码**：下载来的「头条新闻」每露出一截新内容就有一两张 1024² 的图第一次画 —— 解码 13~20ms + 面积降采样
  8~15ms + 缩放 2~6ms，那一帧 35~60ms（🩹 行尾〔慢：…〕直接点名是哪张图）。现在视口上一屏、下三屏里的图由后台线程**先**解码、
  降采样、按框缩放好（`components/image/prefetch.rs` + `host/engine_prefetch.rs`），放进与绘制同一份缓存，绘制路径不变（像素逐字节相同）。
  降采样 / 缩放改在锁外算（后台线程占着锁十几毫秒，引擎线程画任何一张图都得等）。`STORE_APP=news-app MINI_APP=native android-jank.sh store-slow`：
  屏上重复 1.8% → **0.4%**，最长 55 → 33ms，〔慢：解码 / 降采样〕不再出现。`MINI_NO_PREFETCH=1` 关掉做对照。
- **列表底下有个在转的加载圈，上拉加载更多就整帧**：失效分析见「配不上对的那段」里有 CSS 动画就退回整帧。现在按整段动画
  最多画到框外多远（`Timeline::paint_reach` + 子树外包框 + 半条对角线）取切线（`invalidate_grow.rs`）。顺带修了动画包围盒漏算
  **平移**与**溢出框的孩子**（rotate + translateY 的转圈每帧留一圈上一帧的像素，`tests/sdk_damage_grow.rs` 新用例抓到的）。
  还剩：加载更多那一次 setData 整棵重建 25~31ms（模板 7~9 + 布局 10 + 换行 7，`⏱` 行有分段），列表越长越慢。
- **退出小程序时主线程同步销毁引擎**：`MiniProgramView.close()` 改成只同步等「放手 Surface」（0.2~1.2ms），销毁（8~18ms）
  在引擎线程上异步做，下一个引擎建之前等它（`EngineTeardown`）。原生示例从入口页点开是上推、关掉时也改成下拉退出（从前是系统默认的缩放淡出）。
- **输入框与键盘（2026-10-25，轻聊 / 兴趣圈 / 生活缴费）**：
  ① 多个输入框换焦点，旧框留着光标：焦点变了每帧对一遍（`engine_press.rs` `sync_focus_visual`），新旧两框各重画一次；
  聚焦但没输入时照样画占位符（微信如此），`placeholder-style` > `placeholder-class` 的 color > `#BFBFBF`（`tests/input_focus_visual_e2e.rs`）。
  ② 输入框的身份从「标签_x_y」改成模板结构位置（`parser/template/emit.rs`）：聚焦中的输入框一挪位置（键盘弹起列表变矮、表情面板收起）
  焦点就对不上任何节点 —— 光标没了、打的字进不了 `bindinput`。焦点记的框随登记更新（`elements.rs`），光标闪烁重画新位置。
  ③ `bindkeyboardheightchange`（`engine_keyboard.rs`）：宿主推 `keyboardHeightChange` 时送 `{height, duration}` 给键盘所属的输入框，
  失焦后键盘落下那次（高度 0）也送。`height` = 键盘挡住视图的那一截（两份 Android 宿主都改了），页面 `windowHeight - height` 即可见高。
  轻聊聊天页改成 `adjust-position="{{false}}"` + 按高度改列表高：输入条贴键盘、最新消息不被顶出屏幕（`tests/chat_keyboard_e2e.rs`）。
  Flutter 的 viewInsets 逐帧动画，停 80ms 后报一次最终高度（逐帧报 = 逐帧 setData 重排）。
  ④ 用户自己收了键盘（返回键 / 输入法收起键）：宿主送 `escape` 让输入框失焦（与微信一致）；再点输入框原生 Android 用显式
  `showSoftInput(view, 0)`（`SHOW_IMPLICIT` 在用户收过键盘后会被忽略），Flutter 已连着的连接再 `show()` 一次 —— 从前都弹不出来。
  iOS 原生视图还没接软键盘。
  ⑤ 文字框宽按 taffy 取整后少了不到 1px 就被判成两行（「我家」标签挤成竖排）：换行判定留 1px 余量（`measure.rs` `LAYOUT_ROUNDING_SLACK_PX`）。
  ⑥ 无粗体字面（Android 系统中文字体是可变字体）时粗体从前「错 0.7px 再画一遍」，发虚有重影；改成 FreeType 式加粗字形位图（`text/embolden.rs`）。
## 量具与环境（会让你误判）

- **debug 包**是 DEBUGGABLE，量流畅度装 release（原生示例 `./gradlew assembleRelease`，已配 debug 签名）。
  `adb shell dumpsys package <包名> | grep flags=` 里有 `DEBUGGABLE` 就是 debug 包。
- **引擎库与 APK 并行编**：APK 打进旧库，「对比」其实是同一份代码。一个跑完再跑另一个，比 APK 里那份库的 md5。
- **停止标记**：测速脚本只剩 127 帧（≈1.4s）时先怀疑量具（踩坑记录「测速脚本自己坏了」）。
- **`KEYCODE_BACK`**：没有触摸时 ColorOS 把屏降到 60Hz，退场转场一半是「重复」。返回点导航栏的返回箭头。
- **共用手机**：别的检查（`flutter-android-check` / `android-native-check`）会装包、`force-stop`、转屏。
  量之前看一眼 `lastUpdateTime` 与前台窗口；脚本报「前台不是示例 App」「没进到 …」就是被打断了，重跑，不要拿结果。
- **「滑一会儿才顿」先量前后半段**：`android-jank.sh <页>-long` 打「前半 / 后半」各自的重复率，没变差就不是累积问题，
  去看 `🩹 >8ms` 那几帧是什么（多半是某块大东西被逐出画布窗口后滑回来重画）。
- ColorOS 上 App 日志量大了会整段静默；循环里的 `adb` 会吃掉 stdin（一律 `</dev/null`）。

（详情页）里找不到这个 swiper 的盒子，就退回整页重画：详情页每 3.7s 一个 60~72ms 的整帧，接着 0.5s 换页动画里每帧
21ms 整帧。改成找不到就不画（屏上看不见它）。`STORE_APP=news-app MINI_APP=native ENTER_TAP="540 1500"
bash tools/android-jank.sh detail-fastslow`（从首页点进详情再量）：**屏上重复 7.4% / 6.9% → 1.3~1.8%**（原生），
Flutter 1.4~1.5%，引擎整帧 0。直接深链到详情页量不出来（首页没起来，就没有在后台翻的轮播）——
量「从 A 页点进 B 页」的顿挫要用 `ENTER_TAP`。

**「刚开始不卡、滑着滑着卡起来」的底层原因（2026-10-24，诊断 20261024-153306「原生选茶师也是卡顿」/ 153041）**：
uni-app 产物的页面根是一个 `<scroll-view class="page">`（内容多高它就多高，滚的是页面）。引擎给 scroll-view 做了
整段内容的离屏缓存，可 `layout.rs` 在「数据没变、只换了滚动偏移」时也把这份缓存作废。于是：
- 一开始在预画好的条带（视口 ± 余量）里滑：只合成，2ms，**不卡**；
- 滑出条带后每帧都要补条带，**每次补条带都把这个 scroll-view 的整页内容重新光栅化**（ai-result 3705 行 × 1080，
  外加一块 16MB 新画布）：补 30 行桌面 8ms、PLY110 15~23ms —— **卡起来**。别的页面补条带 0.2ms。
改成只换偏移时不作废 scroll-view 缓存（缓存与页面偏移无关；数据 / 图片 / 字体变化照旧作废）：ai-result 补条带
画 p50 8.3 → 0.6ms，真机 `STORE_APP=tea-app STORE_PATH=pages/ai-result/ai-result … x-fastslow` 引擎 >8ms 的帧 0。
判据 `tests/sdk_damage_root_scroll_view.rs`（根 scroll-view 页面，局部 vs 整帧逐帧逐字节一致）。

同一类页面的第二个坑：根 scroll-view 内容不满一屏（不可滚）时，手指在上面拖，`input.rs` 的 `UpdateArea`
每次移动都置整帧 —— tea-app 分类 / 购物车 / 订单详情等 20 多页拖一下每帧整页重画 9~19ms。改成内层位置没变就不重画。
全量体检（`sdk_scroll_bench` 逐页跑 4 个小程序 65 页）：拖动中「整帧·结构 ← engine_input.rs」从 20 多页降到 0。
剩下的「整帧·动画」（real-sample 分类、tea-app 下单成功、sample-app 订单）是页面上有 CSS 动画，另案。

**Flutter 点胶囊 ⊙ 退出一卡**：① 路由退出动画 250ms 每帧要挪 SurfaceView 平台视图，Flutter 跟着平台线程同步出帧，
实测 45 帧/秒、最后一帧 55ms —— 退出改成不做动画（`reverseTransitionDuration: Duration.zero`）；② 平台视图先没、
销毁后到：引擎没了 Surface 回退 CPU 后照样按 vsync 白画，`dispose` 在主线程等放手时排在这些帧后面，tea-app 首页
等了 102ms —— `EngineCore` 丢了 Surface 就停帧（`surfaceLost`）。改后主线程等 0.3~1.6ms，退出那段上屏无 >15ms 的间隔。

**宿主的杂活收进 SDK（2026-10-24，宿主视图改动，按顿挫验过）**：铺满整屏、生命周期、`wx.vibrate*` 触感从原生示例的
`MainActivity` 挪进 `MiniProgramView`（`HostChrome.kt`：挂到窗口时 edge-to-edge、`ActivityLifecycleCallbacks` 跟
resume / pause / destroy、`ComponentCallbacks2` 跟内存告警；`autoEdgeToEdge` / `autoLifecycle` / `hapticFeedback` 可关），
Flutter 插件自带触感。引擎侧：切后台 / 回前台当前页也收 `onHide` / `onShow`（从前只派发 App 级），前后台没变的那次
不派发（Flutter 一次切后台报 hidden + paused 等三条，从前 `App.onHide` 派发三次）。上屏、帧调度没动。
一加 PLY110 release 包：原生 `query-slow` 0.5%、`query-fastslow` 1.4%、`home-fastslow` 1.4%、`resume-scroll` 1.1~1.8%；
Flutter `query-slow` 0.4%、`query-fastslow` 1.4%；引擎 >8ms 的帧 0~2（补条带画 7~8ms 那几帧，改前同样有）。
`android-native-check.sh pixel` 1078×2353 逐像素一致、`MINI_GEOM` 状态栏 120 / 底 41 与改前相同；`func` 从 3 项不过降到
2 项（「回前台后生命周期流水」现在过；剩下的 ActionSheet 遮罩、胶囊「•••」判不出对话框是旧账）。

**对照微信语义的修正（2026-10-24 晚）+ 手机分辨率变了**：手机的 `wm size` 覆盖被去掉，屏幕回到原生 1272×2772
（之前的数字都是 1080×2354 下量的）。`android-jank.sh` 的点击坐标按 1080 宽写死，现在按屏宽等比换算（`D()` 里），
否则 tabBar 点不到、「没进到 pages/query」。同一台手机、同一分辨率下 A/B（原生示例 release 包，GPU）：

最长 88 / 88 / 44ms —— 在同一个波动范围里，不是这轮改动带来的。比 1080 宽时的 1.4% 高，是分辨率大了 38%：
最长的那几帧是列表追加时整层重传（`传 14580KB`、pump 24~27ms）。`query-slow` 0.5%、最长 33ms，与改前一致。

**演示 App 的弹层与图片预览（2026-10-26）**：
